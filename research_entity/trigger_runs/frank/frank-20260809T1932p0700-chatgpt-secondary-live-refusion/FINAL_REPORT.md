## 4. Cycle 1 — internal whole-system fusion

### 4.1 Main architecture pressures

The freshest internal evidence converges on three cross-cutting pressures.

### A. FRANK recurrence must be adaptive but falsifiable

The Loop-of-Loops directive correctly distinguishes:

- low change + low residual pressure: plausible convergence;
- low change + high residual pressure: stagnation/underthinking;
- productive progress;
- divergence/instability.

This is more useful than a fixed loop count as a research hypothesis, but it is not yet evidence that a complex learned halt controller beats a simple event-driven or fixed-depth baseline.

### B. The semantic fabric should shift work off the hot read path

The current semantic-coupling directive proposes:

`source delta -> affected dependency closure -> derived updates -> coherent epoch publication`

so cognition reads a prepared neighborhood instead of globally rediscovering dependencies on every turn. G9 V3 already has `Delta<T>`, `IncrementalReceipt`, `ViewDelta`, `GraphDelta` and a rule that prompt reads never require global recompute.

The remaining research question is not whether incremental computation exists in computer science; it is whether FRANK's semantic graph remains sparse/local enough under real workloads and whether stale omission / false invalidation / hub amplification stay bounded.

### C. Model-internal global availability must stay distinct from system GWT

The project already has a strict receiver-causal decomposition:

`addressability != delivery != reconstruction != uptake != causal use != outcome != re-entry`.

A local 4B may itself develop globally accessible internal representations, but that does not erase the system-level need to measure what happened across FRANK's organs, tools, memory, authority gateway and re-entry path.

## 5. Cycle 1 external research

External evidence was used as mechanism context, not direct FRANK validation.

### Adaptive test-time compute

`Adaptive Test-Time Compute Allocation for Reasoning LLMs via Constrained Policy Optimization` (arXiv:2604.14853) reports matched-budget gains from adapting compute allocation to instance difficulty rather than spending uniformly. This supports testing adaptive recurrence/resource allocation, but it is model-level test-time compute evidence and does not validate FRANK's loop controller.

### Recurrent-depth language models

`Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach` (arXiv:2502.05171) provides evidence that a recurrent-depth model can exploit additional recurrence at inference. Again, this is evidence that recurrence can be useful, not that FRANK should use one specific external recurrence policy.

### Agent context compression

`ACON: Optimizing Context Compression for Long-horizon LLM Agents` (arXiv:2510.00615) reports substantial reductions in peak context usage while largely preserving agent performance. This supports treating peer-to-local backflow as a designed lossy channel with measurable retention rather than as naive transcript copying.

### Model-internal workspace evidence

`Verbalizable Representations Form a Global Workspace in Language Models` (arXiv:2607.15495) reports a privileged verbalizable representation plane in studied language models and functional perturbation effects. Crucially, the paper explicitly does not claim the full biological GNW architecture: the reported broadcast is within a transformer pass and lacks a clean analog of recurrent cross-region biological loops. This directly strengthens the project's type distinction:

`model-internal workspace-like state != FRANK system GWT != effect authority`.

It also does not establish phenomenal consciousness.

### Incremental-computation implementations

Salsa describes on-demand incremental queries with memoization and selective recomputation. Differential Dataflow represents changing collections as deltas and propagates work where changes occur. These are implementation precedents for FRANK's semantic fabric, not cognitive evidence.

Community/local-agent reports were treated only as anecdotal implementation evidence and were not used for scientific promotion.

## 6. Cycle 2 — hypotheses and executable proxy discrimination

### 6.1 Incremental semantic-fabric proxy

A deterministic synthetic dependency DAG with 5,000 nodes was generated. Across 200 single-source mutations, incremental affected-closure recomputation was compared against complete recomputation.

Results:

- exact outputs: `200/200` matched;
- median affected closure: `0.04%` of nodes;
- p95 affected closure: `1.10%`;
- maximum among random mutations: `52.6%`;
- worst tested early hub: `57.72%`.

Interpretation:

- the sparse/local regime strongly supports testing the incremental semantic fabric;
- the hub case falsifies the naive claim that incremental work is always small;
- H1/UDB/ClayGraph need a first-class `update_amplification` metric/tripwire and adversarial hub workloads.

This is synthetic Python evidence, not a production performance result.

### 6.2 Loop-controller safety fuzz

A simple typed controller matching the project's current regime split was exercised across 200,000 randomized normalized states over:

- state delta;
- unresolved pressure;
- marginal utility;
- cost;
- instability;
- remaining recurrence budget.

Safety checks observed:

- stalled high-pressure state incorrectly called convergence: `0`;
- recurrence after exhausted budget: `0`;
- continuation under explicitly high instability condition: `0`.

This shows that the conceptual regime distinction is executable without the obvious safety contradictions in this proxy. It does not show better task performance and does not justify a learned halting policy.

## 11. Architecture delta

The current FRANK architecture should be refined operationally, not expanded structurally:

1. **Keep ClayCode G9 semantic freeze closed by default.** New FRANK needs should first become executable fixtures/records/libraries.
2. **Make system GWT explicitly dual-plane with model-internal workspace observations.** Model readouts may inform system cognition but never self-certify receiver causal use or authority.
3. **Add semantic update-amplification to Harness observability.** Report median/p95/worst affected closure, stale omission, false invalidation and epoch coherence.
4. **Keep recurrence baselines simple.** Fixed/event-driven/post-hoc readout remain mandatory competitors before any learned halt gate.
5. **Treat peer backflow as a measured compression channel.** Compare future utility, provenance retention, contradiction preservation and provider-loss recovery at equal token budgets.
6. **Receipt-bind all integration closure.** Current package/defect state is only as strong as source/runtime-hash-bound executable evidence.
