## Architecture decision

External free APIs/models are modeled as temporary cognitive/execution organs attached to `UCM2_CORE`, never as independent truth stores or authority sources.

The preferred interaction pattern is:

`UCM2 bounded state assembly -> capability router -> local/free external organ -> typed result receipt -> measured UCM2 outcome -> experience record -> state/Hyperposition update`

This preserves one key-module architecture while allowing heterogeneous frontier capabilities.

## Counter-hypotheses

C1. External API integration may increase latency/failure/privacy complexity enough that local models outperform it for most continuous cognition.

C2. Model-provider diversity may create pseudo-swarm complexity without independent information gain.

C3. External embeddings/reranking may improve retrieval scores while weakening reproducibility when provider models change.

C4. A capability router may become a hidden second architecture if routing policy is not itself persisted/queryable in UCM2.

## Required falsifiers

- compare local embedding baseline vs NVIDIA embedding organ on a fixed UCM2 wiki/world/memory retrieval set;
- compare recall-only vs recall+NVIDIA rerank under matched candidate sets;
- deliberately make the external organ unavailable and verify graceful UCM2 fallback without state corruption;
- record provider/model identity and ensure replay detects non-reproducible external outputs rather than pretending deterministic reconstruction;
- verify API output cannot promote a GENERATED/INFERRED claim to VERIFIED without a machine-side test/receipt;
- verify bounded assemblies prevent full-database/private-state leakage to an external provider.
