## Executive synthesis

CC9 solved a downstream problem: once an operation already has canonical semantics, ClayCode can compile its operation-specific causal basis, compositional dependency/effect closure, canonical resource identity, projection receipts and capability/effect checks.

Fusion3 and FRANK C6 expose an earlier problem that CC9 did not solve:

> **Who certifies that the canonical operation actually means what the human/external intent meant?**

A compiler can produce a perfectly valid, well-typed, correctly hashed Clay contract and still formalize the wrong request. This is not a normal type error. It is a **semantic adequacy / intent closure error**.

CC10 therefore introduces the OPEN candidate:

# CC-RC1.5 — Intent-Certified Semantic Lowering (ICSL)

```text
L0 external/human intent
        ↓
probabilistic / model-assisted extraction
        ↓
S.INTENT_PROPOSAL
  HARD requirement
  PROHIBITION
  SOFT preference
  ASSUMPTION
  UNKNOWN / unresolved ambiguity
  requested effect class
  authority references [references only]
        ↓
OP.INTENT_ADEQUACY_VALIDATE
  source entailment
  owner contract
  user confirmation when required
  domain verifier
  test/oracle evidence
  unresolved-effect-critical set
        ↓
S.INTENT_ADEQUACY_RECEIPT
        ↓
trusted OP.INTENT_COMMIT
        ↓
S.INTENT_CONTRACT
        ↓
OP.INTENT_LOWER_TO_COVE
        ↓
CC-RC1.4 CBCC / Clay G10 COVE
  operation-specific causal basis
  compositional closure
  selection dependencies
  projection receipts
  trace ⊆ trusted closure
  capability gateway
        ↓
effect / outcome / re-entry receipts
```

The central new invariant is:

> **compiler correctness != intent adequacy != execution authority**

This is the strongest ClayCode delta of CC10.

- HARD requirements -> invariants/predicates;

- ASSUMPTIONS -> evidence/predicate obligations;

## 3. Independent external research

### Toward a Science of Intent — arXiv:2604.25000

This work independently uses the term **intent compilation** for transforming partially specified human purpose into inspectable artifacts that bind execution. It models open-world residual uncertainty via closure gaps and delegation envelopes.

This means CC10 does **not** claim global novelty for the intent-compilation idea.

The important transfer is that incomplete intent should remain explicit rather than being silently completed by inference.

### FAVA — arXiv:2607.27267

FAVA independently uses an LLM-guided Permission IR to translate ambiguous natural-language tasks into structured constraints, then deterministically lowers that representation into an evidence-backed permission graph and applies SMT authorization before effectful action. Its paper reports **90.5% Decision Compliance Rate** over its aggregate evaluation.

The architectural convergence is strong:

`semantic extraction != deterministic authorization`.

### ETAS — arXiv:2607.17780

ETAS treats agents, prompts, tools, typed memory, approvals, policies and action traces as semantic program elements. It tracks effects/action traces and explicitly separates requested, handled, denied and committed events.

This independently supports keeping intent, requested effect and committed effect as different states.

### COVENANT — arXiv:2607.25400

COVENANT treats natural-language workflow instructions as source programs, compiles them into WAST/WCFG and checks model proposals against compiled requirements before advancing state. It reports **50.00% -> 83.33%** benchmark success and workflow misalignment **42.50% -> 15.83%** on its evaluated cases.

This supports compile-then-execute as an architecture class, not CC10's exact contract.

### SIGIL — arXiv:2607.27309

SIGIL compiles prose skills into typed AG-IR/harnesses and separates model-owned cognition from code-owned mechanism. It reports mandated-step execution rising from about **56% to 86%** and token use around **0.58x** in its evaluation.

Again, this independently supports program structure instead of re-deriving procedure from prose on every run.

### Intent formalization / specification oracle

Current intent-formalization work supplies the strongest counterpressure: a checkable specification can still be the wrong specification. There may be no perfect automatic oracle for whether the formal contract captures what the user actually meant.

This directly motivates `S.INTENT_ADEQUACY_RECEIPT` rather than pretending parser/compiler success closes the problem.

### Semantic parsing / constrained generation

The arXiv bundle also surfaced:
- ZEROTOP's difficulty with missing/unanswerable slots;
- BenchCLAMP / grammar-constrained semantic parsing;
- ACL-2025 SENSE, where directly exposing semantic parses can reduce LLM performance depending on presentation;
- KBSpec 2026, where verifier feedback improves formal-spec verification pass rates;
- XGrammar-2 2026, demonstrating efficient dynamic structured generation.

Transfer: structure and grammar can guarantee form, but do not by themselves guarantee source-intent fidelity or optimal model-facing representation.

## 5. CC-RC1.5 semantic contract

Machine-readable candidate: `CC_RC1_5_ICSL.claycode.json`.

### A. `S.INTENT_PROPOSAL`

Probabilistic/model-assisted interpretation. Carries source hash, extractor/version, typed clauses, source-span hashes, requested effect class and authority references.

**Authority: NONE.**

### B. `S.INTENT_ADEQUACY_RECEIPT`

Carries evidence bound to the exact proposal:
- source entailment;
- explicit user confirmation where required;
- owner-contract evidence;
- domain verifier;
- test/oracle evidence;
- unresolved clauses;
- unresolved effect-critical set;
- verifier semantics/version.

**Authority: fidelity evidence only.**

### C. `S.INTENT_CONTRACT`

Committed executable meaning:
- hard requirements;
- prohibitions;
- soft preferences;
- assumptions;
- effect class;
- authority requirements;
- source/proposal/adequacy hashes.

It is not world truth and not capability.

### D. Effect-tiered adequacy

Candidate policy:
- read-only can tolerate more non-critical unresolved content;
- reversible actions may permit PARTIAL adequacy if recovery is bounded and no effect-critical unknown remains;
- irreversible/authority-changing actions require stronger verified adequacy for effect-critical clauses, then ordinary current capability authorization at release.

The exact production threshold is OPEN and must be measured.

### E. Lower to existing CBCC/COVE

No duplicate kernel:
- hard clauses -> invariant/predicate obligations;
- prohibitions -> deny constraints;
- assumptions -> predicates/evidence dependencies;
- soft preferences -> optimizer terms;
- authority refs -> required caps to verify;
- unknown critical clauses -> cannot silently lower.

Then CC9/G10 continue unchanged with basis, closure, selection, projection and effect checks.

## 6. ClayGraph findings that materially constrain CC10

1. Raw/source intent is a provenance-bearing object, not graph truth.
2. IntentProposal is derived interpretation and may be superseded without rewriting source history.
3. IntentAdequacyReceipt must preserve verifier/extractor/source ancestry.
4. IntentContract may be persisted as a committed policy/task semantic object but is still distinct from FACT_EXACT.
5. L2 native-symbol/codebook projections must be versioned separately from L1 contract identity.
6. Latent activation may make an intent/goal accessible, but activation cannot strengthen its authority or adequacy.
7. Assembly selection cannot replace intent verification; selection receipt and intent adequacy are different boundaries.

These rules preserve G1d's truth/activation/Assembly separation and make replay across extractor/model versions possible.

## Condensed result

> **ClayCode's next missing primitive is not another compact opcode.
