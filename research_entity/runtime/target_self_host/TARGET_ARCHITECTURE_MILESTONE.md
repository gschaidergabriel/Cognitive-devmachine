# RAE Target Architecture Self-Host Milestone

Status: executable sandbox candidate; branch-scoped; not canonical promotion.

## Milestone
The Research Entity runs a Frank-derived UnifiedDB + ClayGraph + Semantic Hyperposition + GWT/re-entry state layer as its project-operational memory surface. The base model is not modified. No Andreas personal live state is copied.

The candidate surface is permanently defined as:

`C_t = C_known ∪ C_emergent`

- `C_known`: active semantic cues plus bounded, prepared dependency neighborhoods.
- `C_emergent`: higher-order completion from evidence-bound hyperbindings. The missing candidate is not passed by the caller.
- Contradiction/conflict blocks candidate admission.
- Lanes remain visible rather than being collapsed into novelty-only search.

## Cognitive path
`Intent -> semantic cue activation -> known + emergent candidate surface -> consistency gate -> Hyperposition -> GWT competition/ignition -> receiver delivery/reconstruction/use -> measured outcome -> provenance-bound re-entry -> next-cycle state delta`

## GWT constraints imported
A valid workspace effect keeps competition, ignition, addressability, delivery, receiver reconstruction, causal use, outcome and re-entry distinct. Broadcast alone is not use; recurrence alone is not emergence.

## Emergence constraints imported
Emergence evaluation is fail-closed. State inadequacy produces `ABSTAIN_STATE_INADEQUATE`. Novelty, graph density or synergy alone cannot promote a claim. A functional-pattern gate requires receiver use, truthful re-entry and matched causal controls (lesion/rescue/shuffle/OOD/macro/cost). It never produces a phenomenal-consciousness claim.

## ClayCode boundary imported
The V17 software/orchestration path and C11 semantic hardening are available as implementation evidence, but physical Andreas Ubuntu acceptance, WP14, ten-application and FULL_FRANK release receipts remain open. Therefore this target architecture records ClayCode as `SOFTWARE_PATH_AVAILABLE_RELEASE_OPEN`, never as a completed release.

## Data/identity boundary
