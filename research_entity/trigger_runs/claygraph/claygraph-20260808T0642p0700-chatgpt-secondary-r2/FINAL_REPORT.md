## Executive synthesis

Generation 0 established the key separation `persistent semantic/evidence graph + transient activation overlay`, a deterministic repository materializer, an explainable spreading-activation query and a retrieval benchmark harness. G1 asks a harder question: **what exactly may the graph become authoritative for, and what must remain exact outside it?**

The strongest result of this run is a three-layer candidate:

`authoritative exact/event stores`
`-> exact anchor index`
`-> temporal/provenance-aware semantic assertion graph`
`-> transient bounded active assembly`
`-> FRANK M.MEMORY_FABRIC / GWT memory candidate`
`-> exact-anchor validation where current truth or authority matters`

The semantic graph can unify relations across FRANK without implying one physical database. Activation can make relevant relations available without making them more true. Current telemetry, `CognitiveFrame` validity, transactional state and capability/effect authority remain exact and externally validated.

The G1 activation change is deliberately conservative. A local five-question self-use proxy found that parent-like unconstrained two-hop activation produced **no mean recall gain over lexical retrieval** (`0.6333` vs `0.6333` recall@5) and slightly worse precision (`0.32` vs `0.33`). A candidate qualified one-hop policy reached `0.80` recall@5 and `0.40` precision@5 while returning slightly less text. This is useful directionally but the corpus/graph are tiny and hand-anchored; it is not promotion-grade evidence.

The database result is equally important: the current measured FRANK source reports **71 live database files**, but this worker can only classify a subset by current role/schema. `consciousness.db` and `world_experience.db` are candidates for **PROJECT**, not physical merge. Hot Thalamus state, Titan/Ego and any safety/invariant authority remain **DEFER/isolated until live verification**. No store is currently assigned `MERGE`.

## 3. External research synthesis

External evidence was kept by source class.

### Standards / authoritative architecture guidance

**W3C PROV-O** supplies stable vocabulary patterns for representing entities, activities, agents and qualified provenance relationships. Transfer: ClayGraph assertions should carry first-class provenance and lineage rather than hiding source identity in text fields.

**Microsoft's Event Sourcing pattern** makes the append-only history the system of record and materializes current/domain views, while explicitly warning that event sourcing adds significant complexity and that traditional data management is sufficient for most systems/components. Transfer: exact/event authority plus semantic projections is plausible; universal migration is not.

### Current implementation evidence

The current **Graphiti** repository documents temporally valid facts, raw episodes as provenance, incremental updates, and hybrid semantic + keyword + graph traversal. Current Neo4j GraphRAG documentation independently exposes hybrid full-text/vector retrieval and graph traversal. These show the engineering pattern is implementable. They do not prove ClayGraph will outperform SQLite/vector baselines on FRANK.

A current open Graphiti issue asking for standardized temporal retrieval benchmarks reinforces the methodological point: production-like temporal graphs still need explicit retrieval-quality evaluation rather than assuming correct storage implies correct recall.

### Preprints

**Zep / Graphiti (`arXiv:2501.13956`)** reports strong author-system results for temporal graph agent memory on DMR/LongMemEval and latency. This is promising but is not independent ClayGraph evidence.

**T-GRAG (`arXiv:2508.01680`)** treats temporal conflict/ambiguity as a core GraphRAG problem and reports gains from temporal retrieval. Transfer: valid-time and supersession are first-class test dimensions.

**Provenance-Enhanced Statements (`arXiv:2606.15246`)** argues that provenance can encode epistemic stance rather than being semantically neutral and develops conflict-preserving attributed worlds. Transfer: ClayGraph should preserve source-attributed incompatible assertions instead of last-write-wins factualisation.

**Incremental view maintenance** work, including property-graph IVM and the 2026 Enzyme system, supports maintaining derived views incrementally and selecting refresh strategies based on cost/workload. Transfer: incremental update should be adaptive with a rebuild fallback, not an ideology.

**CRDT verification** shows strong eventual consistency is achievable for state types with appropriate algebra/network assumptions. Transfer: CRDTs may fit selected distributed projections; they are not a universal substitute for transactions or causal frame validation.

### Community implementation evidence

A practitioner report on r/aiengineering describes correct user-name data present in Graphiti but an irrelevant relationship being returned for “what's my name?”. Anecdotal and uncontrolled, but it illustrates exactly the failure mode G1 observed locally: **correct graph content does not guarantee correct activation/retrieval**.

## 4. G1 semantic architecture

`CLAYGRAPH_SCHEMA.claycode.json` defines the G1 candidate.

### Layer A — exact anchor index

An anchor references an authoritative store/event/record plus revision/timestamp/provenance witness. It does not duplicate authority. Current-state, migration-parity, capability and transactional decisions require exact witnesses.

### Layer B — temporal semantic assertion graph

Meaning-bearing relations are reified enough to carry:

- semantic identity/hash;
- subject/predicate/object or value;
- source/evidence class;
- valid time + observation/transaction revision;
- origin/ingestion/adjudication provenance;
- predecessor/supersession/conflict links;
- `CURRENT | OPEN | SUPERSEDED | REFUTED | NEGATIVE_RESULT | CONTEXT_ONLY | NOT_SELECTED | UNKNOWN | STALE | REVOKED`.

This explicitly prevents last-write-wins from destroying legitimate disagreement/history.

### Layer C — transient activation

Activation is query/cue/frame-dependent and explainable. G1 changes the default from broad two-hop propagation to **qualified one-hop expansion**. Weak navigation edges (`MENTIONS`, generic `RELATED`, broad branch/dependency links) do not automatically expand unless the query/target independently supports them. Longer paths remain possible as an explicit mode, not the default truth-like spread.

An `S.ACTIVE_ASSEMBLY` carries graph revision, basis frame, seeds, activated assertions, exact anchors, conflict sets, activation paths, freshness scope and token budget. It is explicitly `no_authority=true`.

## Final synthesis

The original ClayGraph intuition survives, but in a more precise form.

The promising idea is **not** “replace 71 SQLite files with a graph.” It is:

> **Turn FRANK's exact, heterogeneous, time-varying stores into one coherent semantic relation space that can be activated associatively, while every activated relation remains anchored to exact history/provenance and every authority-sensitive decision can fall back to the exact source.**

That architecture is compatible with FRANK C4's CognitiveFrame, ClayCode CC-RC1.2, Hyperposition's topology separation, GWT's causal receipts and the Emergence intervention boundary. It also matches external temporal-graph/event-sourcing/provenance patterns without inheriting their claims wholesale.

The negative self-use result for broad two-hop activation is useful: it stops ClayGraph from becoming “graph traversal because graph traversal feels associative.” Generation 1 instead treats association as a **selective, explainable, conflict-aware state transition** whose value has to be measured against simpler retrieval.

That is the candidate carried forward. It remains **HOLD**, not canonical truth.
