The owner requires the **Hyperposition Computational Unit (HCU)** to be co-developed directly as
part of every exact `go` macrocycle.

## Product role

The HCU is a separate-host compute organ of the same Mini Entity, not a second entity. Its target is
a software-defined grid of as many approximately-0.8B cognition cells as the measured hardware can
support usefully.

Initial deployment target supplied by the owner:

- KVM 4;
- 4 CPU cores;
- 16 GB RAM;
- 200 GB disk;
- 16 TB bandwidth;
- no GPU assumed.

Primary workloads include:

- persistent causal world-model computation over canonical state;
- strategic supervisor / dynamic candidate-goal formation;
- long iterative and counterfactual simulations;
- Zero cognition-twin modeling from observable evidence;
- falsifiable improvement-hypothesis generation and feedback to Zero/EntityOS;
- free-only LLM feed from the admitted provider/token pool.

Every exact `go` must:

3. keep all HCU-specific data/files under
   `the artefact/MicroEntity/hyperposition_compute_unit/`;
4. rebuild `the artefact/MicroEntity/MICROENTITY_CURRENT.zip` whenever an HCU file or HCU-linked
   MicroEntity package contract changes;
5. never package secrets/tokens;
6. preserve MiniUnifiedDB as canonical durable authority and EffectGate as the only admitted
   real-effect path.

## Computational fabric law

The preferred KVM4 design maximizes logical cells through a shared pinned ~0.8B base runtime plus
cell-specific state/adapters where the runtime permits it. Full independent model copies remain an
alternative, but the admitted resident count is determined only from exact measured RSS/latency.

The HCU is "GPU-like" only as a coordination topology: cells exchange typed candidate/simulation
packets through a scheduler and Hyperposition/GWT bridge. It is not a claim of GPU-equivalent
arithmetic throughput.

## Evidence law

No source-side module-count estimate is runtime truth.

Required promotion measurements include exact per-cell RSS, shared-base incremental RSS, throughput,
latency, scheduler fairness, restart/recovery, generation fencing, MiniUnifiedDB round-trip and
EffectGate isolation.

The separate VPS is a later deployment target. Current repository execution controls remain in
force: VPS/self-hosted/production-host testing cannot mint current acceptance evidence unless a
later explicit owner directive changes that boundary.
