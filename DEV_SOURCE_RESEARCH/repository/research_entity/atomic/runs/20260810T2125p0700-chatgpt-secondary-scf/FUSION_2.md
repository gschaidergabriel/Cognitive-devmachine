# FUSION 2 — after external research

Fresh research collapses any claim that SCF's ingredients are individually new. Static/decentralized labels, capability authority, machine-checkable proof obligations and Petri-net invariants all have strong prior art.

The surviving candidate is narrower and more testable: **compose** those ideas around Frank's already owner-fixed identity/effect/evidence/credit boundaries as one non-generation invariant. The novelty claim is therefore only `NOVEL_COMBINATION_CANDIDATE`.

SCF does not replace the present hard repo/effect gates. It asks whether ClayCode can make semantic privilege creation explicit enough that a compiler or small verifier can reject cross-module identity/authority/evidence/credit minting before runtime effects.

The decisive next test is real-current-trace coverage. If most legitimate transitions require ad-hoc exceptions, or if a conventional multi-label effect system catches the same real defects more cheaply, SCF should be refuted.
