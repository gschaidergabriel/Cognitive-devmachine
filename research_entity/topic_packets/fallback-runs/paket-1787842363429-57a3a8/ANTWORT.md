The observed write‑burst and reclaim‑thrashing stem from the fundamental mismatch between many concurrent meta‑evaluators and SQLite’s single‑writer WAL mode. Even with reduced write frequency or a single rotating evaluator the architecture still serialises all state updates through one DB file, creating a hard contention point that can stall the task pipeline under load. Tuning can alleviate symptoms but does not remove the bottleneck.

Before the system can be called a cybernetic cognition architecture it needs a truly distributed, conflict‑free state substrate (e.g., a replicated log, CRDT‑based store, or actor‑model message bus) that provides bounded‑latency writes, built‑in back‑pressure, and observable causality so that regulation and cognition are decoupled from a single‑point storage bottleneck.
