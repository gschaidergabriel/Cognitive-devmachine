# CCW-001 FUSION 2 — after external prior-art destruction

External evidence destroys any broad novelty story. Read-only derived views are ordinary database machinery. Incremental/materialized view maintenance is mature research and current production engineering. Proof-carrying code already validates proof objects against policy. Provenance research already asks why a derived result holds. Session/refinement/linear type systems already encode protocol progression and logical resources.

Therefore CCW is not a world-first mechanism and is not promoted merely because the phrase 'DONE is a theorem' sounds elegant.

The remaining Frank-specific claim is narrower and falsifiable:

> Given Frank's existing requirement that terminal DONE implies a complete provenance-bound execution -> GWT use -> verified outcome -> causal credit -> admitted delta/no-learning -> re-entry chain, making DONE itself canonical writable state may add a redundant divergence surface. A non-writable causal-closure projection could reduce terminal write/storage state and automatically cease to hold when support becomes invalid, at the cost of read amplification.

The strongest conventional alternative is now strengthened, not weakened: exact canonical references + semantic trigger + REENTERED/DONE in one SQLite transaction + immutable receipt + optional read-time revalidation. This baseline should be expected to win point-read latency and can remove the simple crash window.

The experiment therefore measures three different questions separately:
1. correctness against malformed/mixed support;
2. atomic crash behavior under a strongest conventional transaction;
3. physical write/storage/read trade-off and later support invalidation behavior.

Acceptance is not 'CCW passes'. CCW must show a material property not already matched more simply. Otherwise the durable result should be a design law only: DONE cache/receipt is not sufficient authority; canonical closure must be independently re-derivable.
