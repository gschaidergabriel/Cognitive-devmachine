# RAE Interconnected Research Mesh Protocol

## Core rule

No reserved research trigger is an isolated research silo. Every trigger run MUST begin from the current cross-trigger research mesh and MUST return its durable deltas to that mesh.

The connected research branches are:

- `clay` — integrated Synthetic Clay foundry / master synthesis
- `frank` — FRANK whole-system cognitive/runtime architecture
- `gwt` — Global Workspace mechanisms and causal closure
- `emergenz` — emergence measurement and intervention
- `claycode` — semantic IR / internal language / self-representation
- `hyperposition` — contextual alternatives, higher-order codependencies and dynamic topology

`dump` is an intake/fusion command rather than a peer scientific branch, but its promoted outputs enter the same mesh.

## Mandatory preflight

Before Fusion 1, every research trigger MUST:

1. identify the newest completed material from every connected branch;
2. load the branch's relevant final reports, hypotheses, experiments, negative results, architecture deltas, Topic Packets and micro-packets;
3. preserve evidence status and provenance — synthetic/proxy evidence never becomes live evidence merely because another branch reused it;
4. identify cross-branch dependencies, contradictions, duplicate hypotheses, equivalent mechanisms and unresolved interfaces;
5. materialize an `INTERCONNECT_MANIFEST.json` in the new trigger run;
6. cite the interconnect manifest in the run manifest/final report.

A run that omits this preflight is incomplete and cannot strongly promote architecture/scientific claims.

## Branch dependency priorities

All branches ingest all other branches, but attention is weighted by mechanism relevance:

### `clay`
Clay is the integrated master foundry. It must jointly fuse all branches and is responsible for detecting incompatible local optimizations between them.

### `frank`
Clay is the primary architecture foundation. FRANK MUST start from the newest Clay architecture candidate and then incorporate GWT, ClayCode, Hyperposition and Emergence evidence as subordinate but independent evidence channels. A FRANK architecture proposal that ignores a newer Clay architecture delta is invalid unless it explicitly explains why that Clay result is inapplicable or superseded.

Priority order: `clay -> gwt -> claycode -> hyperposition -> emergenz -> frank history`.

### `gwt`
Must use Clay system constraints, FRANK runtime realities, Emergence causal tests, Hyperposition/context structure and ClayCode representation/receipt semantics.

### `emergenz`
Must use Clay architecture, GWT intervention surfaces, Hyperposition higher-order structure, FRANK runtime observability and ClayCode causal/provenance representations.

### `claycode`
Must use Clay semantic-state requirements, FRANK execution/runtime boundaries, GWT receipt/re-entry semantics, Hyperposition conflict/unknown representation and Emergence observability requirements.

### `hyperposition`
Must use Clay state semantics, FRANK runtime/dataflow constraints, ClayCode representational forms, GWT activation/workspace behavior and Emergence higher-order causal tests.

## Cross-branch contradiction gate

Before final synthesis, every run MUST scan for:

- a new result that contradicts an active hypothesis in another branch;
- a local optimization that worsens a metric another branch treats as a hard constraint;
- duplicated concepts with different names;
- identical concepts with incompatible evidence status;
- a representation claim being mistaken for a mechanism claim;
- an architecture claim depending on synthetic evidence as though it were live evidence;
- stale branch conclusions superseded by a newer run.

Contradictions are retained, not silently averaged away. The final report must state whether each relevant conflict was resolved, narrowed or left open.

## Mesh write-back

Every durable branch result should carry:

- originating trigger/run;
- affected branches;
- evidence class/status;
- upstream dependencies;
- contradictions or supersessions;
- downstream architecture/experiment implications.

Create cross-links in Topic Packets/micro-packets where practical. A branch-specific result may remain local in confidence, but it must remain discoverable by the other branches.

## Scientific boundaries

Interconnection increases information flow, not evidence strength. Repetition across branches by the same underlying source/experiment is not independent replication. Shared ancestry must be tracked so apparent multi-branch agreement is not double-counted.

The mesh never permits GWT, emergence, self-reference or architectural sophistication to be treated as evidence of phenomenal consciousness without separate justified evidence.
