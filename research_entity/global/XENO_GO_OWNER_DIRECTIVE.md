## Architecture objective

Xeno is not merely an agent. It evolves incrementally into a **multi-mode computational unit / cognitive-computer bootstrap**: one coherent system with typed ingress, canonical memory/state, deterministic control, shared model/accelerator resources, logical compute cells, simulation scratch state, J-Space/workspace instrumentation, Hyperposition reduction and a gated effect translator.

The NVIDIA DGX analogy is architectural only: a shared heterogeneous substrate can be reconfigured for substantially different workloads without becoming different products. No NVIDIA-equivalent hardware performance is claimed.

Target cognitive law:

`Zero -> Entity <- Function`

- Zero -> universal typed information ingress/admission, not persistent persona.
- Entity -> causal/state/authority coherence boundary.
- Function -> dynamically allocated cognition/simulation/analysis transforms.
- canonical state/evidence -> outside model-generated cognition.
- EffectGate -> only real/state-changing effect boundary.

A mode changes topology and resource allocation, not canonical truth authority.

## Scaling law

`logical_module_count != physical_concurrent_decode_count`

A future target such as ~600 logical modules on an H100-class accelerator is a **planning hypothesis**. It is not a claim that 600 full ~0.8B models or 600 independent decode streams fit or run concurrently. Shared weights, paged/suspended context state, batching, prefix/KV reuse, quantization and scheduler time-slicing may support large logical populations; exact capacity must be established by measurement.

Every scale claim MUST bind at least:

- exact model/checkpoint/quantization;
- shared-weight residency;
- KV/context bytes per active/suspended branch;
- physical decode concurrency;
- p50/p95 latency and throughput;
- HBM/RAM pressure and headroom;
- scheduler overhead;
- branch independence/correlation;
- restart/recovery behavior.

## World-model law

The previous rule `permanent world simulation = not target` remains true for canonical operation. However, Xeno explicitly prepares **optional experimental world-model and nested-simulation modes** as switchable workloads of the same computational unit.

Thus:

- no permanent duplicate reality is required for normal cognition;
- bounded world-model simulation is allowed and co-developed as an experimental mode;
- full nested simulation may be activated for tasks where measured evidence shows benefit;
- simulated world state remains candidate/projection state;
- observed world outcomes are the calibration authority.

1. Does it improve executable Xeno now?

4. Does it make the later EntityOS computer easier rather than require a rewrite?
5. Does it preserve state/provenance/generation/effect authority?
6. Is the performance/cognition claim falsifiable with executable evidence?

Prefer reusable primitives over mode-specific glue.
