# FUSION 2 — after external collision and executable design

Fresh primary/official evidence changes the novelty interpretation. Chubby already demonstrates that possession of a lock is insufficient for protected operations unless a current generation/sequencer is carried to the operation. Linear/session-typed protocols and practical ownership systems already make protocol/resources non-freely duplicable. Durable workflow event history already provides replayable process continuity.

Therefore the broad LICF ingredients are not novel. The only defensible novelty is the narrow combination: treat the current Frank task continuation as a Clay semantic linear resource that is borrowed by speculative cognition but must be current at every material boundary, and consume/reissue it on material continuation/switch.

The strongest counterhypothesis becomes concrete: a conventional nested fence with `lease_epoch + task_id + task_epoch + material_revision + consent_witness + idempotency_nonce`, checked at the same material boundaries, may produce identical semantic protection with less runtime/wire cost and much less language/runtime complexity.

Executable discrimination must therefore compare LICF against that strong baseline, not merely against the current V15 presence substrate. If equal coverage with higher cost is observed, LICF is not promoted even if it reveals a real missing task-continuity test obligation.
