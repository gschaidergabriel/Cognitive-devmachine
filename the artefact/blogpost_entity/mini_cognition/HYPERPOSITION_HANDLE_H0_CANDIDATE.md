# H0 — minimal Hyperposition handle candidate

Status: RESEARCH_CANDIDATE / NOT_ADMITTED_INTRINSIC / NOT_VALIDATED
Relation to H1: H0 is the more aggressive and architecturally cleaner alternative when canonical runtime already owns the full Hyperposition state.

## Core idea

Do not make the cognition model regenerate a belief distribution that already exists canonically.

Instead of a self-contained transport such as:

`h(c,"a-3|b#e7?d4!6")`

use a canonical handle:

`h(c,7)`

where `7` resolves to one generation/causal-bound Hyperposition object in the canonical runtime/evidence store.

The model receives/uses a handle; it does not mint or overwrite posterior weights.

## Why this is stronger than string compression

The deepest token optimization is **state deduplication**, not punctuation compression.

If the full Hyperposition already exists in canonical state, serializing aliases, probabilities, entropy, provenance and collapse policy into every cognition turn duplicates both tokens and authority.

H0 law:

`CANONICAL STATE ONCE; COGNITION BY HANDLE`.

This aligns with the existing Clay authority split:

`MODEL OUTPUT != CANONICAL TRUTH`.

## Minimal semantics

Candidate intrinsic:

`h(c,ID)`

means only:

`bind/read the admitted Hyperposition view identified by ID into the current cognition object c`.

It grants no mutation, truth promotion, effect authority or cross-generation access.

Fail closed if:
- ID does not exist;
- relation/user/session access fails;
- generation/causal binding is stale;
- evidence/provenance bundle is malformed;
- handle is ambiguous;
- the resolved object violates size/resource policy.

## Model-visible compact view

Runtime may expose a bounded derived view keyed by the handle, for example conceptually:

`H7={a:-3,b:0,~:-8}`

with candidate semantics/aliases already supplied by the bounded context coalition.

That display is **derived context**, not model-owned state. It can be regenerated from canonical evidence.

For binary H, only one relative logit is mathematically necessary. If the full bundle is already visible, even that scalar need not be generated by the model.

## Operations should remain separate

Hyperposition handle = epistemic state reference.

GRF R4 = discriminator proposal.

Omega = structured action candidate.

R6/runtime receipt = fact collapse.

Do not embed all responsibilities into one compact token string merely because it is short.

Recommended separation:

`h(c,7)`

then, only when needed, a separate typed discriminator/action operation using handle 7.

This is more token-efficient and preserves clean authority boundaries.

## H0 vs H1

Use H0 when:
- full canonical Hyperposition exists before model cognition;
- runtime can inject a bounded handle-resolved view;
- model should not alter posterior state directly.

Use H1 only when:
- a portable self-contained derived transport is required;
- round-trip fidelity across a boundary is necessary;
- canonical bundle can still revalidate every compact coordinate.

Preferred architecture hypothesis:

`H0 handle > H1 self-contained > verbose repeated state`

subject to exact tokenizer, parser, task-utility and runtime evidence.

## Token-efficiency claim boundary

`h(c,7)` is only six visible characters, but exact target-tokenizer token count remains unmeasured in this research turn. Character compactness is not token evidence.

The correct benchmark is total turn cost, including any handle-resolved injected view. H0 wins only if:

`tokens(handle + required view) < tokens(verbose state)`

while preserving downstream task utility, calibration, reversal behavior and authority boundaries.

## Strong counterhypothesis

If resolving H0 requires injecting almost the entire verbose state on every turn, the handle only relocates token cost and may add indirection/latency.

Therefore benchmark:
- repeated verbose state;
- H1 compact self-contained state;
- H0 handle + minimal view;
- H0 handle + cached/local model-side state if safely supported;
- no explicit Hyperposition.

## Promotion boundary

No `h(c,ID)` intrinsic should be admitted until exact parser/runtime tests prove:
- read-only semantics;
- generation/causal/user binding;
- no authority escalation;
- deterministic handle resolution;
- bounded context packing;
- exact target-tokenizer net savings;
- matched-budget task equivalence or improvement;
- safe restart/recovery behavior.

Until then H0 is a research compression architecture, not ClayCode syntax.
