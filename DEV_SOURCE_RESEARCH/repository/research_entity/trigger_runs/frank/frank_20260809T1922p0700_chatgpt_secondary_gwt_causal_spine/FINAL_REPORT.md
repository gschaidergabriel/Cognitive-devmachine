## 3. Internal fusion

### FRANK whole-system spine

The current FRANK architecture places bounded ActiveAssembly before GWT competition/broadcast and places verified outcome/re-entry after proposal/effect closure. Therefore the WorkspaceEpisode implementation is a middle causal-measurement layer, not a new authority layer.

### GWT R6 / R8

R6 defines Receiver-Causal Workspace Closure and requires explicit receiver delivery, reconstruction, uptake, local causal effect, joint outcome and provenance-bound re-entry. It also states that broadcast topology and causal-credit topology are not identical.

R8 retains that chain and additionally separates admission from recurrence continuation and semantic-state/version/trace identities. This run therefore does **not** build the adaptive recurrence controller yet. First it makes the causal episode observable enough to test whether such a controller adds value.

### Loop-of-loops directive

The project explicitly retains the counterhypothesis that ordinary event-driven orchestration may be sufficient. The implementation therefore contains `EVENT_BUS` as a matched admission null rather than treating GWT as the automatic winner.

### Emergenz observer-effect re-fusion

A concurrent Emergenz run showed a relevant measurement-validity constraint: logically read-only probes can still perturb physical timing/order, and aggregate equality can hide paired trajectory changes. This run therefore treats its current deterministic reference as semantic-oracle infrastructure only. Live H1 must separately calibrate probe/measurement overhead.

### Harness receipt-sealed determinism re-fusion

A concurrent Harness run sharpened replay identity: semantically active nondeterminism must be deterministic or receipted, while physical execution telemetry should not automatically contaminate semantic equality.

That delta arrived after the first WorkspaceEpisode commit. The code was therefore revised to bind:

- `semantic_contract_hash`;
- `candidate_set_hash`;

- `intervention_hash`;

into episode/receipt identity while preserving existing four-argument `BasisWitness` callers through a backwards-compatible default contract identity.

## 5. Hypotheses and counterhypotheses

### H-FW-01 — receiver-stage closure is necessary for causal diagnosis

If FRANK records only winner/broadcast status, it will conflate addressability with actual downstream use. Explicit delivery/reconstruction/uptake/causal-use receipts should expose failure classes hidden by broadcast-only logs.

**Status:** `OPEN_MECHANISM / EXECUTABLE_REFERENCE_EXISTS`.

### H-FW-02 — GWT admission beats a conventional event bus

Under matched receiver/effect semantics and matched cost, thresholded competition/ignition should improve verified outcome, resource use or correction behavior relative to deterministic event-bus admission.

**Status:** `OPEN / UNTESTED_ON_LIVE_FRANK`.

### H0-FW-02

A conventional persistent event bus is sufficient; GWT admission adds complexity/latency without incremental causal benefit.

**Status:** `OPEN`. The new `EVENT_BUS` mode makes this directly testable.

### H-FW-03 — provenance-bound re-entry has causal value

Truthful receiver/outcome-bound re-entry should outperform provenance-broken shuffled re-entry and no re-entry on later correction/generalization where recurrence matters.

**Status:** `OPEN`.

### H0-FW-03

Re-entry benefit is merely extra context; provenance/order does not matter once content volume is matched.

**Status:** `OPEN`.

### H-FW-04 — semantic receipt identity is the correct replay oracle

Holding semantic contract/state/input/intervention identity fixed should yield deterministic WorkspaceEpisode identity even if irrelevant physical execution metadata differs outside this module.

**Status:** `OPEN_AT_SYSTEM_LEVEL`; local deterministic reference supports only the mechanism shape.
