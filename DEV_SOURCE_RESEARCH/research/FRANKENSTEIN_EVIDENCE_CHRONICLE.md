## 0. Reading rules

A useful Frankenstein history must keep four questions separate:

1. **What did a source claim?**
2. **What code existed?**
3. **What was measured?**
4. **What earned current product/runtime credit?**

Those answers often differ.

Status vocabulary: `attempted`, `source-ready`, `measured`, `reproduced`, `contradicted`, `blocked`, `prepared-not-run`, `adopted`, `retired`.

Evidence vocabulary: `CURRENT_SOURCE`, `HISTORICAL_SOURCE`, `PROJECT_MEASUREMENT`, `EXTERNAL_PRIMARY`, `INFERENCE`, `OPEN_HYPOTHESIS`, `NEGATIVE_RESULT`.

## 2. Why the architecture moved toward a coherent state substrate

### Historical problem

The archive repeatedly contains separate mechanisms for memory, perception, state, routing, tools, goals, reflection and recovery. The engineering failure mode is predictable: if each faculty owns a different durable view of reality, arbitration shifts from “what should I do?” to “which copy of the world should I believe?”

### UnifiedDB direction

Historical/current repository evidence includes:

- `agentZero/code/udb/`
- `research_entity/trigger_runs/unifieddb/`
- archive-assimilation receipts involving UnifiedDB
- later EntityOS authority that keeps canonical durable state outside model-generated cognition.

**Synthesis (`INFERENCE`):** UnifiedDB is best understood as an **authority consolidation**, not merely a storage optimization. One SQLite authority can still expose many typed tables, indexes, views, journals and APIs. High-rate transient state may stay in RAM without becoming a rival durable truth store.

### Emergent Retrieval

Repository search finds explicit “Emergent Retrieval” references in the historical UDB/AgentZero material and UnifiedDB trigger runs.

**Project definition:** retrieval relevance can emerge when independently stored dimensions overlap at query time: semantic similarity, recency, causal lineage, current state, goals, perception, effects, confidence and provenance.

**Not allowed:** claiming the system created information that was never stored or observed.

### External analogy boundary

`EXTERNAL_PRIMARY`: NVIDIA's CUDA Unified Memory documentation describes a programming model that reduces explicit placement/copy burden across CPU/GPU memory and, depending on hardware/software support, offers coherent access models.

**Analogy only:** reducing ownership/copy boundaries can simplify compute over a coherent substrate. CUDA memory coherence does not prove anything about database semantics, retrieval quality or Frankenstein agency.

## 3. GWT / workspace / Global J-Space lineage

The archaeology contains an explicit GWT runtime/history shard (`5f577f3...`). Current EntityOS/HCU work reframes Global J-Space as an empirical coordination/vector-control interface rather than a consciousness claim.

### Current engineering claim

`OPEN_HYPOTHESIS`:

> A measurable shared coordination/vector surface can causally improve arbitration and can generate useful training traces.

### What would *not* prove it

- the model saying it used the workspace;
- repeated semantic labels;
- textual coherence;
- majority agreement across related model calls;
- recurrence of the same workspace content;
- a post-hoc PCA/embedding visualization alone.

### Stronger discriminator

Use exact model/runtime identity and pre-registered interventions:

1. extract/define vector state without answer labels;
2. counterbalance semantic conditions;
3. intervene on the vector;
4. shuffle vector-to-example mapping;
5. lesion/zero the vector path;
6. rescue with the intended vector;
7. measure target behaviour and off-target regressions;
8. preserve family-level splits so near-duplicates do not leak across train/validation/holdout.

**Counterhypothesis:** apparent vector causality is actually prompt/schema leakage or correlated surface vocabulary.

### External research boundary

`EXTERNAL_PRIMARY`: Dehaene & Changeux (Neuron, 2011, DOI `10.1016/j.neuron.2011.03.018`) provide global neuronal workspace theory background. This project does not infer consciousness from that analogy.

`EXTERNAL_PRIMARY`: Zou et al. (arXiv:2310.01405) describe representation engineering around population-level representations and interventions. This supports the general idea that representation-level control can be experimentally investigated; it does not validate Frankenstein's specific vectors.

## 4. Hyperposition: preserving unresolved alternatives

Hyperposition is most useful as an anti-premature-collapse rule:

- competing candidate A and B can both remain represented;
- confidence can stay explicitly unresolved;
- recurrence does not mint fact;
- majority vote does not mint fact;
- a later observation, test or policy can collapse the alternatives.

`OPEN_HYPOTHESIS`: preserving alternatives improves calibration/decision quality versus forced early single-answer selection.

**Counterhypothesis:** keeping alternatives simply increases context length and indecision.

**Discriminator:** matched-token benchmark comparing forced-choice, unordered retained alternatives and structured Hyperposition under the same evidence budget; score calibration, task success, time-to-action and rumination rate.

## 5. Reflection: from recursive prose to a control loop

Historical agent designs often call any self-referential text “reflection”. Frankenstein's stronger formulation is operational:

`state/outcome -> mismatch -> correction -> durable/retrievable update -> changed later behaviour -> exit`

Valid exits include `ACT`, `ASK`, `WAIT`, re-observe, or another measurable state transition.

### Known failure class

`NEGATIVE_RESULT`: rumination/fixation — reflection that recursively produces more reflection without changing action, state or evidence.

### Counterhypothesis

If a reflection condition performs better, perhaps the gain comes only from additional tokens or repeated problem exposure.

### Discriminator

Compare:

- structured reflection with verified outcome feedback;
- equal-token irrelevant prose;
- shuffled prior reflection;
- no reflection;
- reflection with memory disabled.

Measure next-trial success and whether the stored correction is actually retrieved before the changed action.

### External comparison

`EXTERNAL_PRIMARY`: Shinn et al., *Reflexion: Language Agents with Verbal Reinforcement Learning*, NeurIPS 2023, is a relevant design precedent because feedback is converted into reflective language and reused in later episodes. It supports the research direction, not the project's runtime claims.

## 10. GRID10: measurements and why local claims stay local

The current supervisor records a real thread-count A/B on four concurrent processes / four vCPUs:

- 1 thread/process: mean **8.3197 s/call**, 12 samples;
- 2 threads/process: mean **23.1806 s/call**, 12 samples;
- 4 threads/process: **0** completed samples within experiment timeouts.

`PROJECT_MEASUREMENT`.

It falsifies the specific recommendation that two threads/process would improve latency on that measured topology. It does **not** prove one thread is globally optimal for HCU/GRID.

### Why the distinction matters

Logical cell count, resident model count and simultaneous physical decode concurrency are different quantities. A `GRID10` design with ten logical roles need not mean ten resident model processes.

## 12. Agentic substrate hypothesis

The strongest cross-lineage research hypothesis is not “the model becomes conscious”. It is:

> Useful reflective agency may require a sufficiently rich external substrate of typed state, durable memory, perception, arbitration, controlled effects, result receipts and verified outcome re-entry.

`OPEN_HYPOTHESIS`.

### Competing explanations

1. Most gains could come from a larger base model; external substrate adds complexity but little unique value.
2. Retrieval alone could explain gains; workspace/HCU mechanisms may be unnecessary.
3. Tool/result verification may matter, while reflection memory adds little.
4. Structured prompts may mimic the substrate on short tasks, with external state helping only long horizons.

### Discriminator programme

Use matched models/tasks and progressively ablate:

- canonical state;
- causal/provenance identity;
- episodic correction memory;
- perception re-entry;
- workspace arbitration;
- reflection;
- EffectGate/result receipts;
- Hyperposition.

Measure success, calibration, irreversible errors, recovery after disturbance, context/token cost and time-to-action. A mechanism earns architectural credit only when its ablation changes the declared outcome beyond matched controls.
