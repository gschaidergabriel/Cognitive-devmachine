# Zero / J-Space Global Workspace

Canonical workspace for all work triggered by the exact user command `zero`.

## Storage law

All new Zero integrated-workspace work belongs under this tree:

- `concepts/` — architecture/concept sources and consolidated decisions
- `research/` — literature notes, hypotheses, counterhypotheses, experiment design
- `data/` — non-secret measured research data and derived tables
- `benchmarks/` — evaluation specifications/results
- `receipts/` — machine-checkable run/provenance receipts
- `implementations/` — contracts, prototypes, schemas and implementation artifacts
- `ZERO_JSPACE_CURRENT.zip` — current portable Zero/J-Space snapshot

The authoritative persistent product state remains MiniUnifiedDB plus deterministic gates. This directory is the research/build evidence and artifact workspace, not a replacement truth authority.

## Trigger law

`zero` means: work on the integrated Zero cognition architecture and everything required by it:
Unified J-Space/GWT, Thalamus gating, EPQ, GRF, Hyperposition, ClayCode/omega,
the bundled ~0.8B cognitive core, Zero identity projection, targeted Claude Code
inference, adaptive inference-engine integration, receipts, dashboard/visualization,
evaluation, implementation and falsification.

Every substantive `zero` run must:
1. refresh current main and this index;
2. advance or falsify the highest-information Zero/workspace frontier;
3. persist new Zero artifacts under this directory;
4. update `INDEX.json`;
5. rebuild `ZERO_JSPACE_CURRENT.zip`;
6. if MicroEntity product material changed, also update `the artefact/MicroEntity/` and its ZIP.

No secret/API token may enter this tree or either ZIP.
