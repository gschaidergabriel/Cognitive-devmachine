# There are three layers:
#   1 ENTITYOS_ROOTFS_BASE  pristine image, built by vm/build-rootfs.sh
#   2 ENTITYOS_ROOTFS_RUN   ephemeral clone, correctly wiped on start+stop
#   3 the persistent binds  durable state

# 2026-09-07: 6.9G there, incl. the working conversation loop and a 522M

# well. DeviceAllow is NOT optional here: measured DevicePolicy=closed with an
# allow-list of exactly /dev/net/tun, char-pts, /dev/fuse. A bind without the
# matching DeviceAllow leaves the device present but dead inside the container,
# which presents as "Vulkan mysteriously broke after the reboot".
#
# ADDED 2026-09-07, measured after the base-image swap: --bind=/dev/dri alone
# is NOT enough. After a clean restart the container's /dev/dri contained only
# card1 -- renderD128 was missing, and llama-server started anyway and fell
# back to CPU silently, exactly the failure mode start_gespraech.sh warns
# about. The node needs its own explicit --bind. Verified by comparing host
# (card1 + renderD128) against container (card1 only) after the restart, then
# again after adding the line below.
#
# The binds below are a deliberate HOLDING ACTION, not the final layering.
# They are reversible and lose nothing. The correct end state, per artifact
# and per this repo's own stated conventions, is written up in
# /var/lib/entityos/staging-restart/LAYERING.md -- in short: voice CODE, the
