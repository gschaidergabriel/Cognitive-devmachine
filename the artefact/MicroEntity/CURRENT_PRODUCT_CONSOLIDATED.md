# Current MicroEntity product contract

MicroEntity is the user-facing self-hosted configuration and cognition-inspection surface of EntityOS/Mini Entity.

Fixed product components:
1. bundled generic approximately-0.8B local cognition core;
2. fixed/versioned J-Space↔GWT integration around that core;
3. one Cognitive Module ON/OFF control;
4. first-class Claude Code targeted-inference adapter;
5. adaptive capability-driven integration for other models/APIs;
6. model-specific J-Space profiles only where real hookable latent access exists;
7. owner-directed Hyperposition Computational Unit (HCU): a measured CPU-first grid of as many approximately-0.8B logical/physical cognition tiles as the admitted host can safely sustain;
8. persistent HCU strategic/world-model lane for causal projection, dynamic goal candidates, long counterfactual simulation, bounded Zero cognitive-twin modeling and hypothesis feedback;
9. existing FREE_ONLY adaptive inference fabric may feed HCU with candidate data, but external model output remains non-canonical until independently admitted;
10. MiniUnifiedDB/deterministic gates remain truth/state/effect authority and HCU never becomes a second entity/state/effect authority;
11. self-hosted dashboard with explicit first activation, autostart and stable local URL where the host permits it, plus deterministic loopback fallback.

Initial HCU deployment target: KVM 4 / 4 CPU cores / 16 GB RAM / 200 GB disk / 16 TB bandwidth. The target is planning/deployment context, not current runtime acceptance evidence.

Closed APIs are `COMPILED_EXTERNAL` and never represented as hidden-state-integrated. Local hookable models may be `FULL_LOCAL_LATENT` after exact model/profile calibration.

Canonical HCU package: `hcu/`.
Package snapshot: `MICROENTITY_CURRENT.zip`.
All HCU-specific generated source/data/tests/receipts included in the repository package must also be included in the current ZIP snapshot.
