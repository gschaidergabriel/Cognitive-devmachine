# UCM2 KEY MODULE CONTRACT

UCM2 is intentionally developed as one **Unified Clay Machine key module** backed by one fluid typed state fabric.

The research target is not a loose collection of services. The key module must be able to contain and expose, under one persistent semantic root, at least:

- UnifiedDB semantic/state materialization;
- all typed cognitive/runtime states;
- integrated wiki/knowledge;
- memory and experience history;
- self model;
- world model;
- goals/tasks/policies;
- state-machine and execution-continuity state;
- Semantic Hyperpositions and unresolved alternatives;
- GRT/GRF possibility frames;
- GWT/activation/reentry state where relevant;
- modules/organs and their lifecycle/readouts;
- capabilities/API/tool observations;
- experiments, evidence, claims and contradictions;
- provenance, transactions, epochs, replay and recovery state;
- derived graph/topology projections.

`UCM2_CORE` is the root semantic identity of this experimental body. Subsystems may have their own typed objects and execution adapters, but they remain members/views of the same key module rather than independent competing truth stores.

## Fluidity law

The schema and module surface must remain evolvable. New module/state kinds may be introduced through explicit typed migrations/transactions without requiring a new database per organ or feature.

Code is an execution mechanism. Durable meaning, identity, state, lineage and experience must be queryable from the UCM2 state fabric.

## Self-read law

A frontier worker must be able to ask UCM2 to describe its own current state and receive a bounded machine-readable assembly containing the relevant states, world/self model, open Hyperpositions, module state, experience lineage and current epoch.

This self-read is an experiment surface, not proof of consciousness or truth.

## Experience law

Every material interaction by a frontier worker should be able to emit an experience record containing at least:

- actor/worker identity;
- observation;
- prediction or hypothesis;
- measured outcome;
- lesson/update;
- claim class;
- epoch/time/provenance.

Experiences remain evidence-bearing state and are also summarized in append-only work reports. They are never silently converted into verified fact.

## ClayGraph law

Graph/topology is a derived view/index over the key module state. Association, activation, centrality, relevance or higher-order binding may select candidates but cannot mint fact authority on their own.

## Isolation law

UCM2 must never silently write to the main Clay/Frank/ClayVerse canonical databases, work reports or runtime paths. Main/VPS data is imported read-only with provenance and freshness labels.
