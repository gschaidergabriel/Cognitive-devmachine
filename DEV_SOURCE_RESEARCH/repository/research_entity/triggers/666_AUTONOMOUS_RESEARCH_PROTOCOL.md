# Reserved Trigger: `666` — Autonomous Research Genesis

**Status:** PROJECT_OWNER_FIXED_AUTONOMOUS_TRIGGER
**Kind:** phase-sensitive autonomous research meta-trigger
**Home room:** `center`

## Meaning

`666` completely replaces the former `go` command. There is no separate `go` trigger anymore.

On every exact `666`, first read `research_entity/rooms/PROGRAM_STATE.json`, the current Level-0 workspace and the repo-native center state.

### Mode A — Level 0 still open

If `666_RELEASE_GATE != PASS`:

`666 -> join/resume persistent exhaustive Level-0 swarm`

Mandatory protocols/laws:

- `research_entity/triggers/666_ARCHIVE_ASSIMILATION_PROTOCOL.md`
- `research_entity/global/LEVEL0_EXHAUSTIVE_CORPUS_COMPLETION_LAW.md`
- `research_entity/global/LEVEL0_SWARM_EXECUTION_LAW.md`

The meaning is owner-fixed:

`666 + L0_OPEN = SWARM UNTIL L0_PASS`

The Level-0 swarm must exhaustively account for/evaluate the complete frozen Drive corpus and complete frozen Project-Frankenstein Level-0 scope, then perform cross-source reconciliation, branch feedback, earned-work audit and release validation.

A worker does not stop after one arbitrary shard when more non-overlapping executable work is available in the same invocation. It closes/receipts its shard, releases the lease, consumes peer deltas, selects the next highest-value open obligation and continues.

Every active worker discovers peers/tasks/leases before choosing work. Workers route around active leases, cross-read dependencies, pivot at safe points on overlap, and use CAS/current-SHA writes on hot shared state. Sampling may prioritize/shard but never satisfies completion.

The campaign persists in repo state across sessions/instances until PASS. Any later exact `666` joins the same campaign and continues the current rest-obligation matrix rather than restarting. The swarm consists only of actually available/active workers; the protocol must not pretend unscheduled workers are executing in the background.

No stochastic research-field spawning occurs before Level-0 PASS.

### Mode B — Level 0 complete

If `666_RELEASE_GATE = PASS`:

`666 -> spawn one seeded stochastic research field -> act immediately -> cross-connect -> feed findings into the shared research mesh`

Follow:

`research_entity/global/EMERGENT_RESEARCH_FIELD_SPAWNING_PROTOCOL.md`

The spawned field shares the complete common research narrative and knows the current milestone, but does not automatically become a direct implementation worker for that milestone. Diversity and emergent cross-field coupling are intentional.

## Shared milestones

The global milestones remain sequential release gates after Level 0:

`ClayCode BASE -> H1 Reference Harness -> H2 ClayCode Harness -> H3 One-Module FRANK -> UnifiedDB -> LoRA Training Data -> WAIT`

They are the common attractor for the research organism. Specialist rooms own concrete gate implementation/validation. `666` after Level 0 provides exploratory perturbations, cross-domain hypotheses, counterexamples, measurements and new mechanisms that flow into those rooms.

## Autonomous action law

A `666` invocation must not stop at planning when executable/research work is possible in the same invocation.

### Before Level 0 PASS

It must:

1. pulse/read the center and current frozen source scopes;
2. compute the remaining exhaustive obligations;
3. inspect active peers/tasks/leases;
4. claim a highest-value non-overlapping Level-0 obligation;
5. execute real archive analysis/inventory/reconciliation work immediately;
6. publish receipts/manifests/branch deltas;
7. release completed shard leases;
8. cross-read peer results and pivot away from duplicates;
9. claim another open obligation while execution capacity remains;
10. continue until PASS or the current invocation's actual execution surface is exhausted.

### After Level 0 PASS

It must:

1. pulse/read the center;
2. inspect recent spawned fields to avoid duplicates;
3. generate candidate fields using a recorded seed;
4. choose stochastically among high-value diverse candidates;
5. create persistent field state;
6. choose a fitting role/lane;
7. research/build/test immediately;
8. cross-read at least two relevant branches/fields where feasible;
9. publish findings, counterhypotheses, negative results or `NO_CHANGE`;
10. route actionable deltas to specialist branches;
11. preserve provenance/ancestry and evidence class.

## Epistemic law

Randomness generates search diversity, not truth.

No field, worker role, repeated agreement or creator-advisor preference upgrades evidence status by itself.

Before Level 0 PASS, full-corpus accounting outranks novelty: unrelated research-field spawning is forbidden while exhaustive historical obligations remain open.

## Training/spend boundary

`666` never automatically launches paid LoRA training or paid Together inference/training. The staged program stops at WAIT until explicit owner authorization.

## Compatibility rule

Any historical project document that still refers to `go` as the autonomous trigger is superseded by this protocol.

Any older Level-0 interpretation that treats representative sampling, bounded semantic review or one-shard-per-666 behavior as sufficient completion is superseded by the exhaustive corpus and swarm laws.

Canonical compact law:

`666 before L0 PASS = persistent exhaustive Level-0 swarm`

`666 after L0 PASS = emergent research-field genesis`
