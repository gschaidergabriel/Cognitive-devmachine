## 4. Fusion 1 — strongest internal evidence

### 4.1 FRANK is a heterogeneous loop-of-loops, not one magic loop

The strongest current systems hypothesis remains that FRANK should be tested as a heterogeneous typed recurrent dynamical system with local loops that may have different states, rates, delays, budgets, persistence and stopping rules. This is distinct from chain-of-thought and distinct from model-internal recurrent depth.

The critical negative rule remains:

`low state delta + high unresolved pressure = STALLED candidate, not CONVERGED`

A productive bounded cycle is not automatically failure. Recurrence is not emergence.

### 4.2 GWT adaptive recurrence is promising but not promoted

A prior synthetic GWT experiment compared fixed recurrence budgets against adaptive controls over 60,000 authored episode draws per policy. The pressure/trend policy approximately matched the fixed-12 success rate while using about 47% fewer recurrence steps and improving the authored cost-adjusted utility. This supports the *shape* of a trajectory-aware controller, not a live FRANK performance claim.

The retained counterhypotheses are strong: conventional event-driven scheduling may be sufficient; GWT focus may add no incremental causal value; routing overhead may erase step savings; adaptive gates may shallow-halt hard cases; a single global controller may be sufficient.

### 4.3 ClayGraph provenance diversity solves a narrow problem, not everything

The Reversal-Aware Binding synthetic work showed a large benefit for provenance-family diversity against correlated source echo, but it did not improve ordinary true-reversal adaptation and context identity alone solved most of the context-bifurcation problem. Therefore raw repetition and independent support must remain different variables, but a richer graph should not be declared universally superior.

### 4.4 Measurement can intervene

Emergence instrumentation work established a mechanism-level confound: logical read-only status does not imply physical timing noninterference, and aggregate outcome equality can hide paired trajectory flips. This matters near competition, ignition, re-entry and effect deadlines. Observation configuration should remain part of causal-test identity until calibrated against low/no-observation references.

### 5.2 ActiveAssembly reference compiler

A hosted Linux reference execution of `active_assembly.py` passed 8/8 tests. Tested invariants include deterministic assembly hashing under permutation, bounded item budget, stale-epoch exclusion, retained re-expansion references, ancestry-aware conflict retention, and rejection of attempts by model/peer/visual/capability packets to mint execution authority.

A constructed 5,000-trial echo/conflict fixture retained explicit counterevidence in 5,000/5,000 ancestry/conflict-aware selections versus 4,212/5,000 naive top-3 selections at the chosen generator/settings.

This positive result is not complete. A concurrent adversarial counterexample showed that `max_per_ancestry=1` can itself hide one side of an unresolved contradiction when the contradictory propositions share one ancestry family. The corrected rule is therefore:

`shared ancestry must not receive independent-replication credit`

AND

`shared ancestry must not erase unresolved contradiction observability`.

Conflict visibility must be represented independently from ancestry-diversity credit, for example through a bounded deterministic conflict capsule/metadata carrying both proposition identities, ancestry relation and re-expansion refs. This counterexample materially improves the candidate and prevents a false promotion from the earlier 5,000-trial result.

### 5.3 Snapshot -> commit promotion barrier

A hosted component test of `snapshot_commit.py` passed 6/6 tests. It enforces that unrelated state changes need not invalidate an effect proposal, but a relevant dependency version change, capability-epoch change, missing dependency or backwards commit epoch blocks or forces reassembly.

A SQLite WAL runtime proxy reproduced the stale-snapshot problem: after a concurrent writer advanced state, upgrading an old read snapshot failed with SQLite error code 517, `SQLITE_BUSY_SNAPSHOT`. A fresh commit transaction observed the new version and allowed explicit revalidation.

A constructed dependency-change proxy showed why whole-global-epoch invalidation is too coarse: whole-epoch abort was 1.0 whenever any global key changed, whereas dependency-closure abort followed the overlap probability between changed keys and declared dependencies. The exact rates are workload-specific and are not FRANK estimates.

The current architecture candidate is therefore:

`cognition snapshot -> materialize/close -> fresh commit transaction -> revalidate declared effect-relevant dependencies + capability/resource epoch -> deterministic authority gateway`.

If a newly required dependency was absent from the original cognitive snapshot, the system fails closed into reassembly rather than laundering it into the commit.

The same semantic promotion barrier should later be tested not only for external effects but for MVC candidate promotion, durable topology writeback and peer-derived durable state.
