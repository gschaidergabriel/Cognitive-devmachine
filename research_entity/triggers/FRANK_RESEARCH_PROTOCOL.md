# Reserved Trigger: `frank`

Research FRANK as one integrated cognitive/runtime architecture, not as a loose list of services. Use the Master Research Trigger Protocol and mandatory Interconnected Research Mesh Protocol.

## Fixed target architecture — not a hypothesis

Every `frank` run MUST load and obey `research_entity/global/FRANK_CLAY_NATIVE_CONTRACT.md`.

The project-owner-fixed target is a Clay-native FRANK: the abliterated Qwen-class 4B is full-model adapted so Clay becomes its native generated/deliberative symbolic language; memory, values/vector semantics, state, GWT/Assemblies, Hyperposition, inter-module semantic communication and the architecture source itself are Clay-native.

This target itself is NOT an open yes/no research hypothesis. Research evaluates how to realize it, consequences, optimal training/tokenizer/curriculum, representations, safety boundaries, performance, migration and failure modes.

**Needle is the sole intentionally retained non-Clay semantic subsystem.** It remains fully used as the fast classifier/router. Needle output enters Clay as typed provenance-bound input/proposal and never mints authority by itself.

Native code, databases, tensors, vector payloads, KV caches and binary wire formats may implement/encode Clay semantics. They MUST NOT become a second competing semantic architecture. Runtime authority enforcement may be compiled to native code, but its semantic contract is authored in Clay/ClayCode and remains non-self-authorizing.

## Mandatory foundation hierarchy

### 1. Clay — primary scientific/architectural foundation

Load newest completed and fresh in-progress Clay research: architecture candidate/delta, experiments, negative results, Topic/Micro-Packets and cross-branch feedback. Clay is the primary integrated architecture foundation.

### 2. ClayCode — primary FRANK architecture/implementation IR

Deeply ingest newest ClayCode research: semantic IR, typed state/version/provenance/conflict semantics, intent contracts, dependency/effect closure, COVE/MOSAIC integration, reader projections/rails, parser/compiler/self-hosting evidence, runtime ABI experiments and target-reader measurements.

The new FRANK architecture MUST be authored as ClayCode semantic IR. Until a stable surface syntax exists, the authoritative source artifact is:

`research_entity/trigger_runs/frank/<run_id>/FRANK_ARCHITECTURE.claycode.json`

Human-readable reports and implementation-language code are downstream projections/targets.

### 3. ClayGraph — mandatory deep associative-memory substrate

Every FRANK run MUST deeply ingest current ClayGraph completed and in-progress research, including accepted/current graph, newest candidate, schema, evolution decisions, self-use benchmarks, database inventory/migration feedback, semantic epochs, activation/Assembly semantics, exact anchors and negative results.

ClayGraph is the specialist Clay-native associative semantic memory substrate. It does not automatically become the whole persistence/query system and physical graph-store merge remains evidence-dependent.

### 4. UnifiedDB — mandatory deep persistence/query/transaction substrate

Every FRANK run MUST ingest current UnifiedDB research, including its foundation/protocol and newest completed/in-progress runs where present.

UnifiedDB researches the logically unified Clay-native semantic identity, query, persistence, transaction and retrieval plane across exact events/state, temporal/provenance data, graph memory, vector/FTS/materialized indexes, activation/Assemblies/GWT and effect/outcome history.

Hard rule:

> semantic/logical unification does not imply mandatory physical storage unification.

FRANK architecture must explicitly classify physical stores/engines as `KEEP_ISOLATED`, `UNIFY_LOGICALLY`, `COLOCATE_PHYSICALLY`, derived/rebuildable, or otherwise evidence-bounded. Exact/event/effect authority and secrets/capabilities retain replay/isolation semantics independent of database convenience.

A FRANK run that silently ignores newer UnifiedDB substrate evidence is incomplete.

### 5. GWT

Preserve causal-stage distinctions: retrieval/activation, candidate set, competition/selection, configured gate/ignition, semantic WorkspaceEpisode, reader projection/rail, reconstruction/uptake, effect/outcome and re-entry. Physical colocation never collapses scientific stage identity.

### 6. Hyperposition

Ingest current topology/epoch/firebreak research. Semantic class/role, basis/epoch, selection and authority identity must survive optimized physical lowering. One Clay language must not become one semantic failure domain.

### 7. Emergenz

Use current causal-emergence method as a constraint, not an architecture marketing label. No FRANK organ is emergent merely because it is recurrent, integrated or GWT-linked. Preserve prospective prediction, lesion, mechanistic rescue, OOD and multiscale causal requirements.

### 8. FRANK history/runtime evidence

Treat old architecture notes as versioned evidence. Prefer current code/runtime measurements, current store/runtime inventory and current platform traces when accessible. Reuse across branches is shared ancestry, not independent replication.
