### Core
UnifiedDB should not be treated as merely a row-returning database for cognitive retrieval. The candidate architecture is a disposable query-time preprocessor: flat lexical retrieval supplies seeds; ClayGraph performs bounded relation-aware expansion; affordance candidates are compiled from requirement coverage; proof completeness, conflict/unknown state, epoch freshness and evidence lineage are preserved in the receipt. Output remains non-authoritative context and is never a second canonical store.

### Local measured result
On a deterministic synthetic 10-query multi-hop possibility fixture with 400 distractor records, the local component run measured flat lexical retrieval at mean required-evidence recall 0.8833 and top-1 intended affordance 0.30. The possibility preprocessor measured 1.00 recall and 1.00 top-1 on the same fixture. A separate earlier scoring iteration measured 0.85/0.70 for the flat baseline versus 1.00/1.00 after relation-aware proof scoring. The benchmark is synthetic and correlated with implementation design; it is evidence that the mechanism can improve this task class, not evidence of superiority over all databases or retrieval systems.

### Negative evidence / fail-closed checks
Four explicit negative checks passed locally: an ungrounded query abstained; stale source/graph epochs were rejected; a required CONFLICT node blocked candidate admissibility; and two supporting refs with the same `lineage_root` counted as one independent support lineage. Shared ancestry therefore cannot be promoted as independent replication.

### External primary-research fusion
GeAR (arXiv:2412.18431) reports that graph expansion can improve conventional base retrievers on multi-hop retrieval. HippoRAG (arXiv:2405.14831) combines knowledge graphs and Personalized PageRank for associative multi-hop memory. RAPTOR (arXiv:2401.18059) shows retrieval can benefit from preprocessing into a multi-level structure rather than only retrieving flat chunks. LLM-Wiki (arXiv:2605.25480) explicitly frames retrieval for agents as reasoning over compiled, linked structures rather than one-shot lookup. These papers support the architectural direction but are independent external studies on different systems/datasets; they do not validate Clay/FRANK implementation claims.

### Architecture delta
The new reference component is `research_entity/harness/reference/possibility_preprocessor.py`. It keeps source epoch and graph epoch explicit, performs bounded graph expansion, weights mechanism/capability evidence more strongly than generic constraints, penalizes incomplete proof paths, exposes conflicts/uncertainty/missing requirements, de-duplicates support by lineage root, and sets `authority=NON_AUTHORITATIVE_PREPROCESSOR_CONTEXT`. It intentionally persists no second possibility store.

### Counterhypotheses
The gain may disappear on real data; synthetic labels may align too closely with the scoring design; dense or late-interaction retrieval may recover the same evidence without graph complexity; graph expansion may amplify wrong edges or stale structure; fixed relation weights may overfit; and extra preprocessing may lose its latency advantage at FRANK scale.

### Promotion boundary / next build
Do not promote a claim that UnifiedDB is globally more accurate than conventional databases. The next admissible milestone is an exact held-out benchmark on real Clay/FRANK snapshots with null queries, corrupted/stale graph variants, counterfactual edge removals, independent episode/seed units, FTS5/BM25 and dense baselines, and cost/latency/memory accounting. Only if the preprocessor wins reproducibly on the target cognitive-retrieval objective should it be promoted as the default read path.
