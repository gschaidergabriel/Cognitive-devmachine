## Five transformed hypotheses

### H-HF5-01 — MULTI_LAYER_EVIDENCE_IDENTITY_CONTRACT

Release evidence is not one hash. Semantic identity, exact byte identity, producer/build/input provenance and admission authority must be separately bound or bridged by explicit equivalence evidence. The current ClayCode V18 direction has strong bounded candidate evidence, but exact-current committed-byte Ubuntu execution remains the decisive release discriminator.

**Highest-information test:** content-addressed exact-current-byte Ubuntu replay, same-semantics/different-surface canary and stale-receipt rejection.

### H-HF5-02 — MEASURED_CAUSAL_REWARD_SUBSPACE_BASELINE

Historical reward preservation must target the causal reward function that is actually invoked and propagated into state/re-entry, not preserve every historical NAcc label by name. Static archaeology found documentation drift and sparse confirmed exact caller evidence while dynamic/indirect invocation remains UNKNOWN.

Typed or multihorizon reward therefore remains baseline-gated and must beat both the measured historical function and a simpler scalar causal-outcome baseline.

**Highest-information test:** H1 runtime instrumentation of caller/channel/outcome provenance, phasic/tonic state, E-PQ delta and re-entry, followed by matched historical-vs-scalar-vs-typed-vs-multihorizon factorial tests.

### H-HF5-03 — COMPLETENESS_GATED_ADAPTIVE_LIVE_FUSION

Targeted live fusion is a routing mode, not the architecture. In the committed 5,000-delta synthetic falsifier, dependency-aware routing reduced full-payload fanout by about 68.4% versus broadcast but still missed 603 required deliveries when 8% of dependency edges were hidden. A later dual-view ClayGraph+UnifiedDB route with reconciliation reached 0.997 hot-path affected recall and 1.0 eventual synthetic recall, but modeled send-attempt savings versus broadcast shrank to about 10.7%.

Therefore route choice must adapt among targeted, dense and digest modes using dependency span, completeness confidence and measured cost. High-impact invalidations require zero permanent missed recipients after repair; uncertain completeness triggers independent-view repair, anti-entropy, dense fallback or explicit degraded coordination.

**Highest-information test:** the existing converged real-repository Ubuntu replay lane with missing/stale/false edges, projection disagreement, duplicates, causal reorder, crash/restart, Git fallback, false-interrupt measurement and full resource accounting.

### H-HF5-04 — ORIGIN_ARRIVAL_PROJECTION_REENTRY_WITH_OBSERVER_PASSIVITY

Re-entry must preserve causal-origin event identity/time, arrival/application time and projection-derivation identity separately. Effectivized projection deltas cannot replace the authoritative raw event cursor. SQLite WAL/checkpoint semantics make same-file observer backaction empirically plausible.

**Highest-information test:** no-observer vs same-file observer vs isolated observer factorial measuring writer p50/p95/p99, `SQLITE_BUSY`/retry rate, WAL bytes, checkpoint latency, crash/restart, ABA and delayed/out-of-order feedback correctness.

### H-HF5-05 — CAUSAL_RECEIPT_DURABILITY_WITH_MEASURED_COMMIT_POLICY

Causal delivery/replan/effect receipts need durable semantics, but per-record `fsync` is not itself a semantic law. The local candidate microbenchmark measured strict locked per-record fsync at roughly 111.84x the mean cost of buffered append in that environment. A selective-sync shadow was about 2.714x faster than strict-all-receipts and replayed 250/250 deltas plus 500/500 deliveries, but was correctly `NOT_SELECTED`: replay equivalence alone does not prove immediate durability or power-loss safety.

**Highest-information test:** Hostinger Ubuntu strict-per-record vs UnifiedDB transaction/group-commit factorial with latency quantiles, CPU/RSS/I/O, process crash, torn-tail/power-loss surrogate, observer backaction, effect idempotency and 100% authoritative fallback replay.
