## 5. External research fusion

### Recurrent depth / adaptive halting

Recent 2026 recurrent/looped-transformer work (arXiv:2604.07822, 2604.21215, 2607.20519, 2606.18206) supports recurrence as a credible way to trade inference compute for effective depth and supports explicit halting research. It also reports overthinking/trajectory-controller coupling risks. This strengthens the project rule that FRANK must compare adaptive recurrence against fixed-budget and ordinary event-driven baselines and must not equate a small state delta with successful convergence.

### Current 4B runtime target

Official Qwen material now exposes Qwen3.5-4B as a current 4B-class candidate, while Qwen3-4B-2507 remains a relevant baseline. Current llama.cpp issues show that Qwen3.5 integration exists but model conversion, tokenizer, Vulkan/SYCL and backend-specific regressions have occurred. Therefore the model/runtime pair must be selected by Andreas-target Ubuntu measurements; this run does not promote Qwen3.5 merely because it is newer.

### Structured memory/backflow

Recent memory systems such as LeanMem (arXiv:2608.03463), MemRefine (2606.13177), MOSAIC (2607.16211) and Infini Memory (2606.10677) strengthen the hypothesis that memory classes should differ in compression/fidelity and that the active reasoning slice should be budgeted rather than equivalent to all persistent memory. They do not validate FRANK's exact packet format or prove that a graph memory is required.

### Typed host boundary

WASI 0.3 / WebAssembly Component Model now provides typed async component interfaces and explicit resources. This is a useful candidate reference for ClayCode host ABI/FFI design, not architecture authority. FRANK still needs an independent epistemic-action gate because interface/capability safety does not prove that an authorized action is justified by fresh evidence.

### Adaptive visual learning

DINOv2-style frozen features plus simple kNN/linear heads and continual-learning literature make MVC-0/MVC-1 a defensible low-compute first discriminator: frozen feature extractor + prototype/kNN baseline + explicit open-set/confidence + provenance-gated examples. The project must still test Andreas-specific data, forgetting, poisoning, unknown rejection and actual target-hardware cost.

### Community evidence

A targeted community/GitHub search found implementation discussions around Qwen3.5 local inference and thinking-mode/runtime quirks. These are treated as implementation anecdotes/bug leads only and are not used to promote architecture claims.

## 7. Executed experiment this run

`EXPERIMENT_LOOP_HALT_CONTRACT_SANITY.py` generated 4,000 synthetic traces across the four explicit regimes convergence, stall, productive cycle and divergence/overthinking.

A deliberately naive `state_delta`-only halt policy achieved 50% contract classification accuracy, falsely halted all 1,000 stalled traces, and produced a 25% overall false-halt rate. The pressure-aware toy classifier matched the preregistered toy labels on all 4,000 traces and had zero false halts, with fewer mean recurrence steps (9.5055 vs 13.2445).

**Interpretation boundary:** this is not evidence that the pressure-aware controller improves real FRANK cognition. The trace generator encodes the distinctions being tested. The result only proves an implementation/testing point: a delta-only halt criterion cannot represent the project's own stall-vs-convergence distinction, so H1 instrumentation must expose residual pressure/error (or a semantically equivalent variable) before controller selection can be scientifically tested.
