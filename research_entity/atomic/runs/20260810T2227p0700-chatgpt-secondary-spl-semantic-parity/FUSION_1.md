# Fusion 1 — current Frank semantic-boundary problem graph

## Current accepted invariants

1. Native cognitive/model/runtime semantics are ClayCode only; German is a bounded bidirectional boundary codec.
2. The translator may parse/extract/render/mark ambiguity but may not reason long-horizon, mint authority, retrieve memory as an autonomous mind, form goals or mutate canonical world state.
3. Hard acceptance fields include identity/person, authority/permission, negation, modality/uncertainty, temporal scope, numbers/units, provenance, speech-act/effect intent and ambiguity.
4. German source text may remain evidence, but canonical cognitive truth is typed ClayCode.
5. Token auth and client/AI-bridge identity are upstream of translation; token presence is credential evidence, not semantic truth or effect authority.
6. Only one current Frank execution may be active; translator research must not create a second task/authority plane.

## High-leverage failure classes

A. **Correlated round-trip error:** DE_TO_CLAY and CLAY_TO_DE share the same wrong convention, so German->Clay->German appears stable while canonical Clay semantics are wrong.

B. **Hard-field laundering through fluency:** surface realization improves German but changes negation, modality, quantity, person role or permission.

C. **Ambiguity collapse:** one ambiguous German source is converted to a single confident Clay interpretation instead of an unresolved alternative.

D. **Affect/semantics coupling:** ExpressionState changes the propositional or authority-bearing content instead of only realization style.

E. **Parser-valid but semantically wrong Clay:** grammar/type validity is necessary but cannot prove fidelity to the German source.

F. **Shared-model self-validation:** using the same translator/model to translate and judge itself can preserve common-mode errors.

G. **Unknown-field false confidence:** a checker that cannot observe a hard field silently treats it as preserved.

## Strong current baselines

1. typed ClayCode parse/type/effect validation;
2. ordinary bidirectional round-trip testing;
3. same-model backtranslation/self-check;
4. field-by-field schema comparison when both endpoints are already typed;
5. conventional independent second parser/checker;
6. reject/clarify on explicit uncertainty.

## Missing substrate exposed by Fusion 1

The boundary lacks an explicit mechanism for **independent semantic conservation evidence** when only one side is initially typed. A candidate must not claim to prove arbitrary German meaning. It must either:

- extract independently observable constraints from German and prove the Clay candidate satisfies them; or
- return UNKNOWN/AMBIGUOUS where the independent checkers cannot establish the hard field.

This suggests a translation-validator architecture rather than a smarter translator.

## Key discriminator

Construct systematic common-mode translator faults where ordinary round-trip and same-parser backtranslation still PASS. Measure whether independent low-complexity hard-field constraints detect the faults without excessive rejection of valid messages.

## Anti-overclaim condition

If a standard translation-validation + diverse independent checker architecture provides identical coverage/cost, no new architecture is justified. Any surviving novelty must be narrower than generic redundancy, backtranslation, lenses, translation validation or error-detecting codes.
