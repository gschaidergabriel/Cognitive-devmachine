# ATOMIC deep report — CQC-001 Causal Quotient Compiler

## 1. Executive result

This run does **not** promote a new Frank organ, runtime, authority primitive, database architecture, GWT mechanism or Harness change. It produces one testable compiler/research candidate: **CQC-001 — Causal Quotient Compiler**.

CQC asks a narrow but high-leverage question created by the current project laws themselves:

> If historical Frank organs/functions may disappear only after their original causal function is measured, can ClayCode mechanically derive which boundaries are actually redundant under the project's protected interventions and observables, rather than relying on human module names or final-output similarity?

The proposed answer is an intervention-scoped causal quotient. Reconstructed historical/current behavior is represented as a protected labeled transition system. Partition refinement searches for states/functions that cannot be distinguished under the declared protected observable and intervention contracts. Exact duplicates may be fused in a candidate quotient. Historical identities are never deleted; they become lineage members of quotient classes. A `QuotientCertificate` records exactly what evidence supported the merge.

Critically, the certificate is **revocable and scoped**. It never means universal identity. A new material intervention, protected observable, semantic epoch, changed baseline ancestry or replay counterexample invalidates the certificate and forces revalidation/refinement.

The current evidence is synthetic only. CQC is not promoted.

## 2. Why the obvious ATOMIC directions were rejected first

A deep ATOMIC run must not reward novelty theater. Several initially attractive directions were already occupied or falsified by the live project mesh.

The owner-fixed Semantic Coupling Fabric already defines ClayCode semantic dependency extraction, UnifiedDB canonical dependency state, incremental deltas, targeted invalidation, Hyperposition preservation, ClayGraph active projection and prepared hot cognitive neighborhoods. Re-inventing event/delta-driven cognition would not be a radical new candidate; it would duplicate current architecture.

### 2.2 Another effect-generation/authority token was low-value duplication

PR261 has already advanced exact execution-generation fencing, typed provider idempotency and synthetic ACK-loss reconciliation into merged target evidence. GAR previously explored a generative/affine authority-region language primitive and lost as a runtime architecture against a simpler opaque live scoped capability. The remaining effect gaps are important, but a fresh ATOMIC authority token would repeat existing work.

### 2.3 PSW was already refuted as a distinct representation

Possibility State Weave showed useful sparse-state and memoization behavior, but an immutable base + sparse overlay + exact branch identity + pure transition memoization matched the result. PSW remains an implementation envelope, not a new semantic organ.

### 2.4 SPL was already refuted as uniquely useful

Semantic Parity Lattice matched a conventional independent validator in the controlled proxy while costing more. The durable result was the need for independent hard-semantic validation, not SPL itself.

### 2.5 ACEF remains unpromoted

Atomic Causal Epoch Fabric remains a serious transactional candidate, but its strongest task-transaction/belief-transaction counterbaseline is unresolved. CQC must not stack itself on ACEF and thereby hide two uncertainties inside one architecture.

### 2.6 CARF is concurrent but complementary

During this run another ATOMIC worker opened CARF around causal-credit responsibility. Cross-read showed no duplicate work. CARF asks which contributing states deserve credit; CQC asks which states/functions may be safely quotient-merged. If CARF later wins, its credit receipts should simply become protected CQC observables.

## 3. The project-specific gap

The Original Organ / Module Baseline contract is unusually strict and correct: no historical organ/function may be fused, distributed, replaced or redesigned without reconstructing and measuring its role. That law protects the project from the common failure mode where a cleaner architecture silently drops old causal functions.

But the contract is currently primarily an evidence and promotion contract. It does not itself provide a machine-native mechanism for deciding equivalence among measured functions.

This matters because the final target direction is one integrated Frank loop-core / one-module organism. If every historical organ remains an explicit permanent runtime boundary merely because humans named it, the project cannot exploit its owner-fixed AI-native architecture freedom. If organs are fused simply because their outputs look similar, the project risks deleting hidden causal roles.

The missing bridge is therefore:

`Original Baselines + interventions + protected causal receipts -> reproducible candidate fusion partition`.

CQC is one attempt to build that bridge.

## 4. Core CQC semantics

### 4.1 Input

CQC consumes bounded executable/replayable component semantics derived from:

- immutable Original Baseline references;
- ClayCode typed semantic signatures;
- state-transition/re-entry signatures;
- lesion/rescue handles;
- recovery and stale-lineage interventions;
- GWT causal-use receipts;
- effect-authority decisions;
- outcome/credit/learning receipts;
- resource/reliability observables when material to the baseline.

### 4.2 Protected observable contract

The first CQC version treats the following as non-negotiable protected distinctions:

1. semantic and state identity where causally material;
2. provenance and selected-lineage identity;
3. task/output correctness;
4. GWT candidate/selection/delivery/reconstruction/use/local-effect/outcome/re-entry closure;
5. Needle/tool/effect-route choices;
6. effect authorization, reservation, generation and provider-precommit behavior;
7. causal credit and admitted learning deltas;
8. recurrence termination and loop-regime behavior;
9. crash/restart/rollback/rebuild/quarantine behavior;
10. material latency/reliability/resource behavior when the baseline says it changes acceptance.

This list is deliberately broader than final text output.

### 4.3 Intervention alphabet

A quotient is meaningful only relative to an explicit transition/intervention alphabet. Candidate families include:

- normal cognitive transitions;
- lesion and rescue;
- truthful/shuffled/provenance-broken/no-reentry controls;
- stale epoch/generation transitions;
- authority break/denial/revocation;
- crash/restart/rollback;
- delayed/reordered inputs;
- memory/receiver route removals;
- Hyperposition simplification controls;
- future component-specific fault injections.

The alphabet is part of the evidence object, not an implicit assumption.

### 4.4 Partition refinement

CQC starts with states/functions grouped only when protected current observations match. It then repeatedly splits a class whenever members transition under any declared action/intervention into different equivalence classes or produce different protected observables.

At a fixed point, the quotient represents the coarsest equivalence supported by the bounded model and declared contracts.

This is established bisimulation/partition-refinement territory mathematically. The project-specific part is which Frank semantics are protected and how the result is connected to immutable historical lineage and promotion gates.

### 4.5 QuotientCertificate

Every proposed quotient carries a certificate including at least:

- candidate/compiler version;
- source semantic/graph epoch;
- Original Baseline IDs/hashes;
- protected observable contract/version;
- intervention alphabet/version;
- partition/equivalence hash;
- test/replay/recovery corpus hashes;
- lineage map from every historical/current unit into quotient classes;
- negative/counterexample set;
- status and invalidation reason.

A certificate never grants effect authority and never authorizes architecture promotion.

### 4.6 Invalidation law

The most important CQC law is not the merge law; it is the split law.

Any of the following invalidates a universal use of an old quotient:

- new material protected observable;
- new material intervention/failure class;
- changed semantic epoch that alters relevant semantics;
- changed Original Baseline ancestry;
- replay/rescue counterexample;
- target-VPS differential failure;
- held-out/OOD causal mismatch;
- effect-authority or recovery mismatch.

The correct interpretation is therefore:

`no distinguishing counterexample inside certificate scope`,

not:

`these organs are metaphysically identical forever`.

## 5. Synthetic discriminator

### 5.1 Construction

The reference model contains 96 states:

- 6 externally visible groups;
- 4 hidden causal modes per group;
- 4 implementation duplicates of every causal mode.

Normal actions intentionally hide the four causal modes. This simulates a dangerous situation in which multiple implementations look identical on ordinary user paths.

Four intervention families expose latent distinctions:

- `LESION`;
- `REENTRY_SHUFFLE`;
- `STALE_EPOCH`;
- `AUTHORITY_BREAK`.

The four implementation duplicates are truly equivalent and should be compressed. The four hidden causal modes are not equivalent and should remain separate.

The test corpus contains all action sequences of length 1, 2 and 3 plus 500 seeded length-4 sequences, yielding 104,064 trace comparisons per architecture.

### 5.2 Full no-fusion baseline

- classes: 96;
- compression: 1.0x;
- transition entries: 768;
- violations: 0 / 104,064.

This is the safety ceiling and compression floor.

### 5.3 Output-only quotient

- classes: 6;
- apparent compression: 16x;
- table reduction: 93.75%;
- inconsistent block/action pairs: 24;
- violations: 74,112 / 104,064;
- violation rate: 71.2177%.

This is intentionally unsafe overcompression. It demonstrates why final output equivalence is not a valid organ-fusion criterion.

### 5.4 Normal-path bisimulation

- classes: 6;
- apparent compression: 16x;
- violations: 74,112 / 104,064;
- violation rate: 71.2177%.

Adding recurrent transition equivalence does not help when the action alphabet omits the fault/intervention dimensions that reveal the causal modes.

### 5.5 Random size-matched fusion

A random 24-class partition matches CQC's final class count but has:

- 192 inconsistent block/action pairs;
- 104,064 / 104,064 trace violations.

Therefore CQC's result is not explained by merely choosing 24 classes.

### 5.6 CQC intervention-aware quotient

- classes: 24;
- compression: 4x;
- transition entries: 192;
- table reduction: 75%;
- inconsistent block/action pairs: 0;
- violations: 0 / 104,064.

CQC removes exactly the four implementation duplicates per causal state and preserves every modeled intervention-distinct causal mode.

### 5.7 Local refinement cost

On the local Python reference environment:

- N = 200 refinement runs;
- p50 ≈ 0.194 ms;
- p95 ≈ 0.216 ms;
- min ≈ 0.191 ms;
- max ≈ 0.326 ms.

Environment: Linux 6.18.35 x86_64, glibc 2.41, Python 3.13.5, GCC 14.2.0, 5 visible CPUs. CPU model was unavailable. No GPU/network used.

These numbers are only a tiny local algorithm proxy. They are not target-VPS or compiler evidence.

## 6. Intervention ablation

The ablation produced a useful warning against naive test-count thinking.

Normal-only gives six classes and 71.2% failure.

Normal + `LESION` gives 12 classes but still ~49.73% trace failure.

Normal + `REENTRY_SHUFFLE` gives 12 classes but still ~49.64% trace failure.

Normal + `STALE_EPOCH` alone happens to separate all 24 causal classes in this construction and yields zero test-corpus violation.

Normal + `AUTHORITY_BREAK` alone also separates all 24 classes here.

Normal + `LESION` + `REENTRY_SHUFFLE` separates all 24 classes.

Therefore individual intervention names are not intrinsically sufficient or necessary. What matters is whether the chosen intervention set separates the causal equivalence classes relevant to the protected contract. Real CQC needs intervention-coverage measurement and adversarial counterexample search, not a checklist count.

## 7. Prior-art adjudication

External primary-source research destroys broad novelty claims.

Known families include:

- bisimulation/state-space minimization and partition refinement;
- bisimulation-based RL state abstraction;
- causal dynamics/state abstraction;
- causal abstraction validated through interchange interventions;
- soft-intervention causal abstraction;
- approximate state abstraction with bounded behavior loss;
- equality saturation / e-graphs for non-destructive compiler equivalence spaces.

Therefore:

- CQC is not new mathematics;
- causal intervention testing is not new;
- state quotienting is not new;
- non-destructive equivalence search is not new;
- approximate abstraction is not new.

The surviving novelty class is only `NOVEL_COMBINATION_CANDIDATE`: integration of those ideas into ClayCode's historical-organ dissolution gate with Frank-specific protected causal receipts, immutable ancestry and revocable evidence certificates.

No world-first claim is made.

## 8. Strongest counterhypothesis

The strongest conventional baseline remains unresolved and may kill CQC:

> Keep explicit organ boundaries during validation. Build a purpose-specific protected regression suite with lesion/reentry/authority/recovery tests. Apply ordinary compiler optimization. Let researchers manually authorize fusion only after matched evidence.

This approach may achieve equal safety and reproducibility with much less compiler infrastructure.

The synthetic model does not measure:

- developer effort;
- compiler complexity;
- maintenance cost;
- stochastic LLM state abstraction;
- actual historical organ redundancy;
- target-VPS resource savings;
- real Frank causal fault coverage.

Therefore the counterhypothesis status is **UNRESOLVED_AND_STRONG**.

CQC should be rejected if that baseline matches protected defect coverage, replay/recovery parity and reproducibility with materially lower implementation/resource complexity.

## 10. What CQC could change if it survives

If real evidence later supports it, CQC would alter the architecture development process more than any single organ:

Historical names such as Thalamus-like gate, GWT selector, NAcc-like persistence controller, Needle route subloops, memory services or other legacy modules would no longer automatically map one-to-one to final runtime objects. Their causal functions and lineage would remain visible, but the physical/semantic implementation could be extracted from equivalence classes justified by interventions.

This is consistent with the AI-native architecture freedom directive: human intuitiveness and biological metaphors are not architecture authority.

The gain is potentially threefold:

1. **compression** — remove genuine duplicate state/functions;
2. **safety** — stop output-equivalent but intervention-distinct functions from being fused;
3. **reproducibility** — make the reason for a fusion machine-replayable rather than a prose design judgment.

None of these gains is yet measured on real Frank.

## 11. Main failure modes

CQC could fail badly in at least these ways:

1. **incomplete observables** — a causally important state variable is omitted;
2. **incomplete intervention alphabet** — states look equivalent until an unseen failure mode arrives;
3. **state-space explosion** — exact causal minimization becomes too expensive;
4. **stochastic instability** — LLM/model variability prevents stable equivalence classes;
5. **false split explosion** — noisy resource/timing observables make every state unique;
6. **approximation leakage** — learned similarity merges authority/recovery-distinct states;
7. **certificate churn** — frequent new evidence invalidates quotients faster than they save complexity;
8. **compiler semantic debt** — host-language instrumentation secretly defines the real equivalence instead of ClayCode semantics;
9. **baseline insufficiency** — historical archaeology is too incomplete to justify any quotient;
10. **counterbaseline domination** — manual protected regression is simply cheaper and just as safe.

These failure modes are not edge cases; they define the real experiment program.

## 13. Final verdict

**CQC-001 survives ATOMIC as a test obligation, not as a promoted architecture.**

The strongest positive result is not the synthetic 4x compression. The strongest result is the sharper architectural law exposed by the experiment:

> Frank organ/function fusion must be judged against intervention-scoped protected causal equivalence, not final-output similarity or happy-path recurrence alone.

The strongest negative result is equally important:

> Existing bisimulation/causal-abstraction/compiler research supplies most of the mathematical machinery, and a conventional protected regression/manual-fusion path may still dominate CQC.

That is the next falsifier.
