## Question

Can schema-v2 UCM2 reject a legacy v1 database containing non-replay-complete semantic history **before any database migration write**, while still allowing the only lossless legacy case — root-only epoch 0 — to bootstrap into a valid replay-complete v2 stream?

## Historical source reconstruction

The exact pre-v2 UCM2 source was re-read at parent commit `76dc52d7b15150cf58ff4e8d2d232a2fac9e9837`.

Observed v1 properties:

- `SCHEMA_VERSION = 1`;
- no `prev_hash` column;
- events hashed only `[epoch, event_type, object_id, payload]`;
- object upsert events stored only kind/status/version, not the full object payload/timestamp/root needed for deterministic replay;
- link events stored only relation/destination, not the full edge reconstruction payload;
- experience events stored only id/actor/claim class, not the complete experience record;
- initial root-only boot had epoch 0 and no event rows.

Therefore a v1 database with any semantic mutation cannot be upgraded to v2 replay authority by filling missing information or merely relabelling the schema.

## Build mutation

Patched `runtime/ucm2.py` so `__init__` runs a read-only preflight **before** the normal read-write connection and `_init()` migration path.

The preflight opens an existing database with SQLite URI `mode=ro` and classifies it:

1. non-existing/empty DB: normal fresh v2 initialization;
2. current schema v2: normal current path;
3. schema v1: requires the exact lossless bootstrap state — epoch 0, zero events, zero edges, zero experiences, exactly one `UCM2_CORE` root object of kind `clay_machine_key_module`;
4. any v1 history/nonzero epoch/extra semantic state: fail closed with `UCM2_V1_HISTORY_NOT_REPLAY_COMPLETE`;
5. missing/incomplete/unknown schema: fail closed with an explicit preflight error.

Only the root-only epoch-0 v1 case reaches `_init()`, where v2 adds `prev_hash`, advances the schema marker and creates a replay-complete `BOOTSTRAP_ROOT` event from the still-present root materialization.
