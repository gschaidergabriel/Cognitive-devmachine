# G5 Architecture Delta

The G5 candidate extends the G4 Semantic Causal Kernel without replacing conventional host/runtime layers.

1. **Canonical event/provenance truth** — append/version identities, claims, source lineage and effect receipts.
2. **Contextual hyperposition** — preserve branch/conflict/unknown/revocation; expose typed role-aware relations through a backend-neutral ABI.
3. **Incremental causal projections** — disposable derived views; track `R_delta`, change amplification, invalidation cost and rebuild crossover.
4. **Bounded activation/assemblies** — activation is relevance, not truth; coordinate active records, context/KV budget and broadcast fanout.
5. **GWT** — receipt-linked `candidate→compete→ignite→broadcast→reconstruct→effect→outcome→reenter`. Latent workspace probes are an independent evidence channel when available.
6. **ClayCode** — typed `PURE_TRANSFORM`, `STATE_PROPOSAL`, `EFFECT_PROPOSAL`; grammar constraint → state constraint → deterministic validation.
7. **Authority/effect gateway** — capability scope, current root, nonce/expiry, policy/invariants, rollback and effect receipts. Model text never self-authorizes.
8. **Execution** — pure/state work may be speculative/local; effect/conflict boundaries pay synchronous synchronization cost.
9. **Platform adapters** — Linux reference and Android/edge/other hosts implement the same semantic contract with hardware-specific inference, memory and thermal policy.

## New control principle

Do not maximize connectivity, broadcast, context or cache independently. Allocate a shared **causal budget** while monitoring semantic completeness, `R_delta`, latency, recovery, energy and effect safety.
