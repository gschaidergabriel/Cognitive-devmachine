# MicroEntity package root

Canonical product-facing package workspace for the Mini Entity / EntityOS MicroEntity surface.

This directory owns the package-facing view of:
- bundled ~0.8B cognitive core integration;
- fixed Unified J-Space/GWT Cognitive Module;
- first-class Claude Code adapter;
- adaptive model/API engine profiles;
- Hyperposition Computational Unit (HCU) modular ~0.8B grid;
- persistent causal-world-model / strategic-supervisor computation as a bounded Mini Entity organ;
- self-hosted MicroEntity dashboard and activation/autostart contracts;
- package manifests, product implementation artifacts, tests and receipts.

`MICROENTITY_CURRENT.zip` is the current portable package snapshot. It must be rebuilt whenever
this package or a linked product architecture contract changes.

## HCU packaging law

All HCU data, architecture contracts, hardware profiles, capacity-planning code, tests and generated
package metadata live under `hyperposition_compute_unit/` and are included in
`MICROENTITY_CURRENT.zip`.

The HCU may later run on a separate VPS, but it remains inside the same Mini Entity. It may not
create a second durable identity, second truth authority, second effect path or second recovery
ledger. MiniUnifiedDB remains canonical durable authority and EffectGate remains the only admitted
real-effect path.

The Zero research workspace lives at `research_entity/global/j-space/`.
Zero-trigger changes that affect the product must update both package roots and both ZIPs.

Secrets/API tokens are never packaged.
