# Current MicroEntity product contract

MicroEntity is the user-facing self-hosted configuration and cognition-inspection surface of EntityOS/Mini Entity.

Fixed product components:
1. bundled generic approximately-0.8B local cognition core;
2. fixed/versioned J-Space↔GWT integration around that core;
3. one Cognitive Module ON/OFF control;
4. first-class Claude Code targeted-inference adapter;
5. adaptive capability-driven integration for other models/APIs as optional workers/fallbacks, not internal cognitive dependencies;
6. model-specific J-Space profiles only where real hookable latent access exists;
7. MiniUnifiedDB/deterministic gates remain truth/state/effect authority;
8. self-hosted dashboard with explicit first activation, autostart and stable local URL where the host permits it, plus deterministic loopback fallback;
9. Hyperposition Computational Unit (HCU): reactive script-first world-model substrate and resource-adaptive logical grid of ~0.8B module roles over a bounded resident worker pool;
10. bounded high-specificity ClayCode projections from HCU to Zero to reduce Zero cognitive load;
11. local HCU semantic/J-Space field replaces provider-specific embedding/prestage dependencies in canonical internal cognition;
12. FREE_ONLY external models remain optional candidate workers/feeds or direct targeted fallbacks only.

The HCU world model preserves an explicit overlay of accepted history/knowledge, measurements, hypotheses, counterhypotheses, forecasts, falsifiers and UNKNOWN regions. Higher-order coupling/emergence remains measurable, intervention-bound and falsifiable rather than authority by coherence.

HCU reference deployment target supplied by the owner: KVM 4, 4 CPU cores, 16 GB RAM, 200 GB disk, 16 TB bandwidth.

Closed APIs are `COMPILED_EXTERNAL` and never represented as hidden-state-integrated. Claude Code may receive compiled Global-J-Space/ClayCode/vector projections and return candidate inference; direct private Claude latent access remains unobserved unless a future admitted mechanism measures it.

The HCU does not create a second entity or second truth store. MiniUnifiedDB remains canonical; EffectGate remains the real-effect boundary.
