## Main findings

### 1. Control metadata is part of model behavior unless structurally isolated

`k531` introduced explicit language-control nudges near generation because the system prompt alone did not reliably determine language. `k529` then changed `[Reply in English]` to `[lang:en]` because the model was directly referencing the control string in user-visible responses. `k539` made language an explicit persona/session policy state.

Transfer: control planes, user content and model-visible context are not automatically separate merely because developers conceptually label them differently. Where possible, use structural control fields/adapters, and test for control-token leakage and instruction-order sensitivity.

### 2. Prompted diversity is not automatically emergent autonomy

`k532` replaced a repetitive idle-thought mechanism with 24 rotating prompt templates across eight categories, an anti-repetition system prompt, a larger token budget and relaxed reflection gates. The commit reports more diverse thoughts afterward, but the mechanism itself establishes a strong scaffold.

Transfer: any claim of spontaneous/autonomous diversity should be evaluated against prompt-pool, repetition-guard and threshold ablations. Diversity generated by a diversity prompt is useful behavior, but it is a different evidence class from unscaffolded emergence.

### 3. Scarce-model routing needs a reversible state machine

`k534` implemented heavy-model mutual exclusion: park/mask Llama, stop it, start Qwen, health-check, restore Llama after idle, define lock ordering, and roll back on failure. The mechanism explicitly represented active model and parked state.

Transfer: GPU/model resource arbitration should be modeled as serialized transitions with invariants, health probes and rollback; process start/stop calls alone are not an adequate state model.

### 4. Internal state availability and salience/disclosure are separate policies

`k535` retained an `[INNER_WORLD]` block but changed prompt rules so internal values shaped tone/behavior silently and were not routinely read back to the user. This is a concrete precursor to salience routing: a datum can be present without being salient or reportable.

Transfer: GWT/context systems should represent at least availability, trust/evidence class, salience/attention and disclosure/action authority separately.

### 5. Generated documentation is an untrusted evidence source until verified

The strongest negative result in the shard is `k540`: a 2384-line generated documentation file was removed because it fabricated named development-team members and authoritative-looking project history. `k541` adds another warning: its commit title says a complete ARCHITECTURE.md was added, yet the exact ordinal diff returned for this commit only changes the GPU line, while the frozen root already contains the large architecture document.

Transfer: generated docs must carry provenance and claim classes. Person/team/history claims require entity verification; architecture claims require diff/tree/runtime corroboration. Commit messages and prose are secondary evidence, not ground truth.

### 6. Philosophical provenance is distinct from implementation proof

`k530` added the GRF paper and a documentation mapping between philosophical principles and Frank subsystems. This is important project provenance and design intent. It is not, by itself, scientific validation of the philosophical framework, phenomenal consciousness or uniqueness of the implementations.

Transfer: preserve design-theory lineage, but keep theory-to-code mappings in a separate evidence class from runtime measurements and causal/phenomenal claims.

### 7. Release integrity is architecture correctness

`k542` made launchers self-locating instead of relying on one hardcoded home path. `k543` added model SHA256 verification, target-mount disk-space checking and bounded Ollama startup handling. The frozen root already contains centralized paths, GPU portability work and release artifacts.

Transfer: reproducible releases need portable path resolution, artifact integrity verification, environment-aware preflight and target-like clean installation tests.
