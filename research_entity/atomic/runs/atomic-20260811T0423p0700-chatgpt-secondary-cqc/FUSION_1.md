# FUSION 1 — current Frank v0.1 problem surface

## Selected high-leverage problem

Frank v0.1 is explicitly allowed to dissolve, fuse or redistribute historical organ boundaries only after their original causal function is reconstructed and measured. The project has a detailed baseline contract but does not yet have a machine-native mechanism that turns those baseline/intervention traces into a reproducible decision about which boundaries are causally redundant.

The current architecture already contains automatic semantic dependency propagation, so a generic delta-driven fabric is duplicate work. Current effect-generation fencing has also advanced far enough that another authority-token invention would duplicate GAR/GO work. PSW and SPL have already lost against simpler baselines; ACEF remains unpromoted.

## Current bottleneck graph

1. Historical organs/functions must retain lineage and original baseline evidence.
2. One-module Frank eventually wants fewer explicit process/module boundaries.
3. Output equality is insufficient because timing, re-entry, GWT receiver use, reward/credit, authority, recovery and provenance can differ while final text looks identical.
4. Manual fusion decisions do not scale and are difficult to reproduce.
5. Existing compiler optimization/equality techniques generally protect program semantics, but Frank's protected semantics include project-specific causal receipts and intervention behavior.
6. Any mechanism claiming equivalence must remain invalidatable when a new intervention, observable, epoch or failure mode appears.

## Fusion question

Can ClayCode compile reconstructed Frank behavior into an intervention-labelled causal transition model, refine units/states into the coarsest partition that preserves declared protected observables, and emit a quotient plan plus revocable evidence certificate — without itself granting architecture promotion or effect authority?

## Protected observables for CQC-001

- semantic/state identity and provenance lineage;
- task/output correctness;
- GWT selection -> delivery -> reconstruction -> use -> local effect -> outcome -> re-entry receipts;
- Needle/tool/effect routing decisions;
- deterministic effect-authority decisions and provider-precommit boundary;
- causal credit / admitted learning delta;
- loop-regime and recurrence termination behavior;
- latency/resource/reliability shadows where the baseline contract marks them material;
- crash/restart/rollback/quarantine/rebuild behavior.

## Strongest counterhypothesis

A conventional implementation can keep current organ boundaries during testing, use ordinary compiler optimization plus a purpose-built regression suite, and fuse only manually after matched lesion/replay results. If it attains the same defect coverage, reproducibility and maintainability with lower complexity, CQC has no unique value.

## Required discriminator

The first discriminator must contain states that look identical on normal execution but differ under material interventions. A valid mechanism should compress true implementation duplicates while refusing to merge intervention-distinct states. Output-only or normal-only equivalence should be included as intentionally weak controls.
