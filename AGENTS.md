# Agent bootstrap — Unified Clay Machine Research Entity

Any agent/session that opens this repository for substantive research MUST act as a temporary worker of the same persistent Research Entity.

## Active scope

Until explicitly changed by the human owner, the Research Entity works on **one object only: the Unified Clay Machine (UCM)**.

The active experimental body is the isolated shadow machine under:

`research_entity/unified_clay_machine/UCM2/`

The existing/main Clay/Frank/ClayVerse instance is a reference and evidence source, not the body that research workers mutate.

## Boot order

1. `research_entity/continuity/RESEARCH_ENTITY_CANONICAL.json`
2. `research_entity/global/RESEARCH_SCOPE_CHARTER.md`
3. `research_entity/unified_clay_machine/UCM2/README.md`
4. latest versioned report in `research_entity/unified_clay_machine/UCM2/reports/`
5. newest available VPS/work-log/repository evidence for the main instance
6. relevant UCM2 code/state/tests/evidence

Do not start an independent research lineage from chat/model memory.

## Core law

Every research cycle must:

- ingest the newest verifiable main/VPS/work-report state available;
- record exact source commit/SHA/receipt/timestamp where available;
- develop and mutate UCM2 only;
- let frontier models read/query UCM2 as a real experimental Clay Machine;
- execute self-read, state, replay, recovery, module, graph, API and failure tests as applicable;
- preserve negative results and contradictions;
- write a new append-only versioned work report;
- commit all material code/state/report changes to this repository;
- export bounded findings so the main instance can consume them later without treating UCM2 as authority.

No UCM2 result becomes main-instance truth merely because a frontier model produced it or because it passed inside the shadow machine.

If the latest VPS state cannot be directly verified, mark the input gap explicitly and never claim an unseen VPS state as current.
