# FRANK ASYMMETRIC INSTANCE MEMORY RESEARCH CONTRACT

Status: PROJECT_OWNER_FIXED_RESEARCH_TARGET
Date: 2026-08-09
Reference implementation lineage: `gschaidergabriel/frankv0.1`
Research actor architecture: RAE remains separate from Frank identity.

## Research target

Investigate and validate an asymmetric multi-instance Frank architecture in which:

- local Frank is the final embodied base-of-truth/materialization point;
- every cognition instance may maintain its own UnifiedDB materialization;
- Claude Code, ChatGPT and comparable high-capability instances synchronize intelligently at rich semantic resolution;
- the local Clay-native 4B does **not** receive a full replica of their working cognition;
- instead, high-capability instances compile cognitively compressed, evidence-preserving backflow suitable for the 4B's smaller capacity;
- external instances are represented inside local Frank as dynamic body/capability extensions whose implications can affect GWT selection, delegation and self/world modeling.

## Key distinction

Do not treat all nodes as equal replicas.

Research two explicit channels:

### High-capability peer channel

Rich semantic exchange among Claude Code, ChatGPT and comparable nodes:

- packet deltas;
- provenance/evidence;
- contradictions;
- temporal validity;
- tool/effect/outcome receipts;
- file/artifact topology;
- world/self/Andreas updates;
- hyperposition alternatives;
- research/harness deltas;
- candidate durable knowledge.

### Local 4B backflow channel

Bounded semantic return into local Frank:

- durable new knowledge;
- corrections;
- changed world/self/Andreas assumptions;
- capability/body-extension implications;
- changed order/dependency logic;
- changed file/artifact topology;
- reusable procedures;
- failure patterns;
- verified outcomes;
- unresolved conflicts that must remain unresolved;
- minimum provenance needed to preserve epistemic role.

The 4B should not be forced to ingest remote scratch context, verbose traces or low-value working state.

## Body-extension hypothesis

Adding an external instance should be modeled as expanding Frank's body/cognitive affordance field.

Research whether local Frank performs better when each attached instance is represented not only by provider/model metadata but by inferred actionable implications:

- what becomes possible;
- what becomes cheaper/faster;
- what new information becomes reachable;
- what authority/privacy boundaries change;
- what dependencies appear;
- what is lost when the instance disappears.

Test whether this representation improves autonomous delegation, recovery, planning and user outcome.

## Clay-native structural derivation hypothesis

Investigate whether file placement, artifact lineage and operation ordering can emerge from typed Clay semantic relations rather than manual lists.

Candidate relation primitives include:

`contains, depends_on, supersedes, generated_from, canonical_for, moved_to, requires_before, produces, consumes, owned_by, valid_for_epoch`

The target one-binary Frank should derive transient operational topology from these packet relations.

## Compression research

The central scientific question is not generic summarization. It is **future-use-preserving cognitive compression for a 4B embodied model**.

Required evaluation dimensions:

- future task success after compression;
- correction retention;
- provenance retention;
- contradiction retention;
- world/self/Andreas model fidelity;
- file/order reconstruction accuracy;
- capability implication recall;
- causal procedure retention;
- remote-detail re-expansion success;
- compression cost/latency;
- local inference latency/RAM/token impact;
- omission-induced failure rate;
- stale-memory rate;
- Goodhart resistance.

## Required baselines

Compare at minimum:

1. full rich state copied into a stronger model;
2. naive text summary into 4B;
3. retrieval-only pointers with no durable compression;
4. fixed-size semantic packet backflow;
5. adaptive task-independent cognitive backflow;
6. adaptive backflow plus on-demand remote re-expansion.

The target should only be promoted if it preserves materially relevant behavior better than simpler baselines under equal or lower local compute/memory cost.

## Conflict law

Local Frank is canonical integration/base-of-truth, but local origin does not create epistemic superiority.

Peer conflicts remain explicit.

Research fusion must preserve:

- source identity;
- observation time and valid time;
- evidence class;
- confidence/uncertainty;
- alternative states;
- supersession/retraction lineage.

Never collapse a Claude/ChatGPT/local disagreement into one value merely to make replicas converge.

## Promotion criterion

A proposed backflow/sync mechanism is not accepted because it feels elegant or human-like.

It must demonstrate measured gains or preserved function under matched traces, including real Andreas usecases where available, with regression tests for misunderstanding, stale state, file/order errors, capability loss and peer conflict.
