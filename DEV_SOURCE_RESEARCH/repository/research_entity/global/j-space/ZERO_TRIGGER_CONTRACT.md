# ZERO trigger and persistence contract

Exact trigger: `zero`

Compact semantics:

`zero -> refresh -> integrated Zero/J-Space/GWT work -> test/falsify -> persist under research_entity/global/j-space -> update index -> rebuild Zero ZIP -> update MicroEntity package/ZIP when product-relevant`

Scope includes Zero identity, GRF, Hyperposition, Unified Cognitive Workspace Fabric,
Thalamus, EPQ, ClayCode/omega, bundled ~0.8B integration, Claude Code first-class
targeted inference, adaptive model/API backends, telemetry, dashboard, tests,
research data, receipts and implementation artifacts.

Hard laws:
- J-Space + GWT are one cognitive fabric.
- Zero is an EntityOS runtime identity/configuration, not Claude Code.
- Claude Code is a first-class targeted inference engine.
- Other engines use capability-adaptive profiles.
- Local hookable models may have real model-specific latent/J-Space integration.
- Closed APIs use compiled external control; never claim hidden-state access.
- Model/J-Space output cannot mint canonical truth/state/effects.
- Every produced Zero artifact goes into this tree.
- `ZERO_JSPACE_CURRENT.zip` is rebuilt from the current admitted package set.
- Secrets are excluded.
