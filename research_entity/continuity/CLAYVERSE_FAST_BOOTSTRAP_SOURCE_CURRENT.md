## 1. CENTRAL COGNITIVE PRODUCT LAW

ClayVerse must accumulate **two different kinds of durable experience**:

1. **Evidence memory — WHAT is known**
   - facts;
   - decisions;
   - commitments;
   - tasks/open questions;
   - preferences;
   - observed outcomes;
   - state/world/wiki knowledge;
   - provenance and counterevidence.

2. **Method memory — HOW problems are solved**
   - reusable problem-solving frameworks;
   - bounded heuristics;
   - hypothesis/counterhypothesis structures;
   - useful intervention/test patterns;
   - failure patterns;
   - counterexamples;
   - scope limits and falsifiers.

This is a system-level **meta-learning / analogical-transfer layer** around Claude Code.

ClayVerse must become better at novel and out-of-distribution problems by reusing validated methods from structurally similar earlier problems, while preserving the hard boundary:

> EXPERIENCE MAY IMPROVE HOW CLAYVERSE SEARCHES, REASONS, TESTS AND LEARNS; EXPERIENCE MUST NOT SILENTLY MANUFACTURE TRUTH.

Mandatory invariant:

`FACT_UNKNOWN + METHOD_PRESENT != FACT_PRESENT`

An analogy may tell ClayVerse **how to investigate** an unknown. It may never turn the unknown into a fact.

All durable evidence memory and method memory live in `UnifiedDB`.

MicroClay is an internal persistent adaptive retrieval organ of the one ClayVerse entity. It is not a second agent, personality, identity or source of truth.

MicroClay may learn:

- cue/query normalization;
- best memory/source/class entry route;

- graph seed/radius/widen thresholds;
- evidence-vs-method route priors;
- context-budget packing;
- abstention/UNKNOWN thresholds;

MicroClay may **not** learn or mint:

- semantic truth;
- provenance;
- durable facts merely because retrieval scored them highly;
- user rights/privacy boundaries;
- EffectGate policy;
- EntityOS capability authority;
- cross-session access beyond explicit collision rules;

Normal Claude completion is not reward.

Learning must be causally/outcome bound. Verified task/effect outcomes, explicit corrections, retrieval misses, stale-state use, unnecessary personalization and method-transfer success/failure are admissible learning signals once their contracts are explicit.

Adaptive policy starts in `SHADOW`; promotion to active serving requires isolated replay/held-out evidence.

## 3. REQUIRED MEMORY CLASSES

Current `durable_memory.kind` is flexible. The finished product must validate and explicitly admit method-memory classes equivalent to:

- `framework_candidate` — newly abstracted reusable method, not promoted;
- `framework` — promoted reusable problem-solving framework;
- `heuristic_candidate` — candidate bounded rule-of-thumb;
- `heuristic` — promoted bounded heuristic;
- `failure_pattern` — recurring strategy/mechanism failure with conditions;
- `counterexample` — evidence limiting or falsifying a framework/heuristic;
- `method_receipt` — provenance/evaluation/promotion/demotion/use receipt.

Existing evidence classes such as `fact`, `decision`, `task`, `commitment`, `preference`, `open`, and `open_question` remain distinct.

Method memory must never be silently mixed into factual memory.

## 5. TWO-STAGE RETRIEVAL LAW

ClayVerse retrieval must separate evidence retrieval from analogical/method retrieval.

### STAGE A — EVIDENCE

Flow:

`current cue + user/session/resource context`
→ MicroClay evidence entry proposal
→ exact/structured temporal/FTS/vector candidates
→ bounded ClayGraph activation
→ provenance/valid-time/conflict/privacy filters
→ adaptive ranking/budget/abstention
→ `PRESENT | UNDERCOVERED | UNKNOWN`

Evidence context contains admitted facts/state/tasks/decisions and their provenance/counterevidence.

### STAGE B — METHOD / ANALOGICAL TRANSFER

Stage B may activate when at least one bounded trigger is present:

- Stage A returns `UNKNOWN`;
- evidence coverage is below an explicit threshold;
- problem appears structurally novel/out-of-distribution;
- evidence conflicts leave the solution method unresolved;
- the user/task explicitly asks for strategy, diagnosis, planning, hypothesis generation or investigation method.

Stage B searches `framework`, `heuristic`, `failure_pattern`, and `counterexample` by **structural problem signature**, not lexical similarity alone.

Stage B output is `method_context`, never factual truth. It should include where available:

- candidate framework(s);
- structural-match explanation;
- preconditions to verify;
- strongest failure pattern/counterexample;
- discriminating tests/searches/interventions;
- calibration/confidence and provenance.

Direct contradictory evidence outranks analogical method context.

## 6. ABSTRACTION / FRAMEWORK CREATION

After a solved or failed causal episode, ClayVerse may create a `framework_candidate` by stripping instance-specific names/values while preserving causal and structural relationships.

The abstraction should capture:

- problem structure;
- hypotheses and strongest counterhypotheses;
- observations/evidence;
- interventions/tests;
- decisive discriminator;
- solution path;
- failure paths;
- conditions where the method would be inappropriate;
- unresolved uncertainty.

A single success is insufficient for universal promotion.

Candidate creation must not erase the source episode or its negative evidence.

---

## 7. PROMOTION / DEMOTION LAW

Promotion from candidate to reusable `framework`/`heuristic` requires bounded evidence such as:

- provenance-complete source episode(s);
- explicit falsifier/counterexample search;
- evidence that the method transfers beyond one memorized instance;
- replay/held-out/cross-instance validation where practical;
- no increase in contamination, stale-state use, privacy leakage or authority leakage;
- negative outcomes preserved as negative evidence;
- calibration recorded.

Frameworks must be demotable or retired when counterevidence accumulates.

MicroClay learns **accessibility/routing capital**, not framework truth or promotion authority.

Critical anti-self-reinforcement rules:

- retrieval score is not truth confidence;

- direct contradictory evidence cannot be overridden by a preferred analogy;
- failed methods remain available as `failure_pattern`/`counterexample` evidence.
