# Fusion 1 — current problem surface

The active program has one target: finished `self.root` / Frank v0.1. The current workspace still marks the cognitive loop core, UnifiedDB continuity, GWT/Hyperposition, proactive agency, memory/reward/goals, security/recovery and end-to-end acceptance as open. The loop-of-loops directive specifically requires slow reward, personality/homeostatic and memory updates after verified outcome and causal credit, plus anti-stagnation/overcoupling control.

The current mesh has recently made rapid progress on execution exclusivity, token ingress, idempotency, effect authority and ClayCode WP04. Those are therefore poor ATOMIC choices for this invocation because active workers already own them. F-V01-11 remains comparatively under-instantiated on the current target branch.

The important design tension is not merely "how to retrieve old text". Frank needs at least four properties simultaneously: long-horizon usefulness, bounded context/storage, resistance to self-reinforcing echoes and stale strategies, and strict separation between instrumental usefulness and epistemic/authority semantics. A memory that happened to improve a task must not become a fact, SELF, user intent or effect authority. Conversely, a low-frequency identity or safety anchor must not be forgotten because it earns little task reward.

A very simple conventional baseline is stronger than it first appears: keep versioned/provenance-bound verified state, use explicit supersession, and retrieve the newest exact valid record before reaching for utility-weighted heuristics. Any radical candidate must beat that baseline rather than only beating naive semantic similarity.
