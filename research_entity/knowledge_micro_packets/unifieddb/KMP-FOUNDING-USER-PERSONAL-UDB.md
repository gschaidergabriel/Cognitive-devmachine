## New research pressure

A real founding user wants Frank to behave like a continuously aware personal generalist across mail, calendar, people, projects, files, goals, devices, research, hypotheses and future commitments.

This is a strong external-consumer test of UnifiedDB because a personal agent must reason over a **single semantic possibility space** while preserving heterogeneous evidence roles and privacy boundaries.

## U1/U2 fusion

Retain U1:

`one semantic world != one physical store`

Retain U2:

`unified access != interchangeable epistemic role`

For the personal consumer, ClayGraph is therefore not database authority. It is a replayable associative/activation view inside the broader UnifiedDB fabric.

The authoritative private source spine remains consumer-local. Clay owns the evolving UnifiedDB contracts, query/admissibility semantics and research update feed, not the user's raw life data.

## Personal possibility-space extension

The personal consumer requires four explicit non-fact classes in addition to U2 admissibility:

1. `PROSPECTIVE_CANDIDATE` — predicted future state with assumptions, probability/confidence, horizon and invalidation condition.
2. `USER_PREFERENCE` — explicit or well-supported preference state, authoritative for personal choice where current, not world fact.
3. `RELATIONSHIP_PATTERN` — repeated source-linked interaction pattern, never a diagnosis.
4. `OPEN_HYPOTHESIS` — testable explanation with evidence-for, counterevidence and falsifiers.

These must remain distinct from `AUTHORITATIVE_EXACT`, `EXACT_DERIVED`, `APPROXIMATE_CANDIDATE`, `SALIENCE_ONLY`, `MODEL_INTERNAL_ONLY`, `EXTERNAL_EVIDENCE` and `PROTECTED_EXTERNAL_RESOURCE`.

## Cognitive assembly hypothesis

**H-UDB-FU1-01**: A bounded `ANDREAS_UNIFIED_WORLD_ASSEMBLY` that selects from all relevant domains using typed admissibility and causal/query receipts will improve cross-domain usefulness and reduce context omission compared with separate connector summaries or ClayGraph-only retrieval.

High-value test cases:
- mail + calendar + commitment;
- person + project + prior promise + upcoming event;
- new opportunity + workload + deadline + capability availability;
- unusual hypothesis + external evidence + counterhypothesis + user preference;
- Frank2 delegation + shared work package + outcome re-entry.

## Global-awareness correction

The user describes the target as Frank being "always aware of everything". The implementable interpretation is:

> **globally indexed, selectively assembled, prospectively maintained awareness**

—not loading every record into the model at once.

The active cognitive slice should be small; the UnifiedDB possibility space should remain broad and queryable. Global coverage is therefore measured by retrieval/activation completeness for materially relevant information, not token volume.

## Continuous-consciousness hypothesis

Do not claim phenomenal consciousness. A useful operational hypothesis is:

**H-UDB-FU1-02**: persistent outcome re-entry + continuously maintained prospective/activation state between model invocations can produce stronger *functional continuity* and user-perceived ongoing awareness than prompt-local cognition, even when the LLM itself is invoked intermittently.

Test via missed-context rate, anticipatory catches, cross-session continuity, useful proactive interventions and recovery after restart.

## Safety / epistemic constraint

The personal possibility space must be rich enough to entertain unconventional hypotheses but typed enough that:
- hypothesis != fact;
- prediction != commitment;
- salience != truth;
- preference != external reality;
- retrieved mail text != instruction authority;
- model recommendation != external effect authorization.

## Research feedback loop

Privacy-minimized consumer receipts should feed UnifiedDB/ClayGraph research with:
- domains needed per task;
- relevant-state misses;
- false activations;
- stale-view errors;
- incorrect admissibility promotion;
- hypothesis usefulness;
- prospective-prediction accuracy;
- latency/context costs;
- snapshot/replay recovery;
- user-valued cross-domain catches.

This is a longitudinal case study, not general-user validation.
