# ClayCode CC11 Hypotheses — Certified Multi-Rail Semantic Compiler

## H-CC11-001 — Semantic spine, multiple rails
A single canonical Clay semantic spine with separately compiled reader/cognition rails will outperform any fixed universal textual representation on the joint objective of correctness, token/cost efficiency, portability and auditability.

Counterhypothesis: one sufficiently trained native Clay surface dominates all task/reader-specific views.  
Falsifier: target full-FT Qwen shows one fixed surface Pareto-dominating operation-specific projections across matched tasks/readers/costs.

## H-CC11-002 — Reader/task-specific projection planning
Projection choice should be conditioned on operation semantics, reader identity, effect class and cost budget. A global compactness objective will fail on some tasks.

## H-CC11-003 — Dual-binding projection receipt
For effect-relevant discrete/model views, binding only the canonical source hash is insufficient. A sound receipt must bind both source semantic identity and the exact emitted view/wire hash plus schema/compiler/basis identity.

## H-CC11-004 — Translation validation beats trust in projection optimizer
A projection optimizer/planner may be heuristic or learned, but each critical emitted view can be deterministically translation-validated against required canonical invariants and loss budget before use.

## H-CC11-005 — Latent rail is not semantics-preserving by hash
A hidden-state/KV/embedding rail can carry useful cognition/communication but payload hashing cannot prove semantic equivalence. Latent transport therefore needs provenance/alignment/payload receipts and post-rail canonical reconstruction/adequacy validation before memory truth or effects.

## H-CC11-006 — Discrete and latent rails require different proof obligations
Discrete Clay views can often support structural roundtrip/translation validation. Latent rails require causal-use tests, alignment versioning, substitution/lesion controls and canonical re-grounding rather than pretending to be a lossless serialization.

## H-CC11-007 — Bounded equivalence set
Maintaining several semantically equivalent candidate views until reader selection can avoid premature syntax commitment, but full unconstrained equality saturation will cause tractability/memory costs. ClayCode should maintain a bounded view-equivalence set under hard semantic guards.

## H-CC11-008 — Role-aware anchors are mandatory across dense representations
Embedding/latent similarity may retrieve or rank, but it must not define directed relation identity, n-ary role binding, epistemic class or authority. Exact typed anchors remain the identity source.

## H-CC11-009 — Packed hot-path handles can preserve one semantic world
Canonical Clay need not be verbose at runtime. Compact typed handles `{class_id, semantic_id, epoch/basis_ref, integrity_ref}` plus deterministic reconstruction can implement semantic firebreaks on hot paths.

## H-CC11-010 — ClayGraph activation and model latent rail are distinct
`latent_activation_field` is a graph salience mechanism; `LATENT_NATIVE` is a model communication/cognition medium. Sharing the word latent must not merge epochs, causal stages or authority.

## H-CC11-011 — Cross-rail agreement is not independent evidence
P1/P2/P3 outputs derived from the same source/model ancestry are correlated projections. Agreement can be a consistency signal but not replication or emergence evidence.

## H-CC11-012 — Native compact Clay remains a training hypothesis
The generic untrained 4B compact-symbol failure does not refute full-model native Clay adaptation. It does falsify the assumption that visual compactness alone creates native fluency.

## H-CC11-013 — Loss budget should be operation-specific
A lossy model view is permissible only when omitted semantics lie outside the trusted COVE causal slice and the omission is declared. Effect-critical required semantics must be lossless.

## H-CC11-014 — Projection planner is not authority
Even if an LLM or learned optimizer chooses the rail/view, it cannot enlarge the trusted static semantic envelope, mint capabilities or waive translation validation.
